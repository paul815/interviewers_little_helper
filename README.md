# Interviewer's Little Helper

Локальный ассистент для качественных интервью по Zoom: в реальном времени расшифровывает
речь интервьюера и респондента в раздельные транскрипты, раз в 4 минуты сравнивает разговор
с гайдом исследования через локальную LLM и показывает в окне поверх Zoom
(по умолчанию — правая половина экрана во всю высоту: слева созвон, справа помощник;
размер меняется и запоминается):

- **чеклист покрытия тем** — covered / partial / not_covered;
- **подсказки** — какие темы пропущены и готовые формулировки вопросов;
- **пробинг-вопросы** — уточнения по интересным свежим репликам респондента;
- **темп интервью** — успеваете ли пройти гайд за отведённое время;
- **экран интервью** — оригинальный текст гайда крупным шрифтом, комментарии
  с отметкой времени и вопросом, под которым они написаны, и список
  «спросить дополнительно» с галочками;
- живой транскрипт с **флагами** (клавиша F5 — отметить яркий момент).

Точность держат сверочные проходы: каждый 4-й цикл перепроверяет последние минуты разговора
(ловит темы, пропущенные в отдельных циклах), а на «Стоп» весь транскрипт прогоняется целиком.
После сессии на диске: транскрипт (JSONL + Markdown), состояние покрытия, история рекомендаций
и **отчёт** — резюме, тезисы по темам, непокрытое, отмеченные моменты. Гайды сохраняются в
**библиотеку** и переиспользуются между интервью серии.

Серии живут **проектами**: проект помнит свой гайд, словарь терминов и длительность,
складывает интервью в отдельную папку и показывает сводное покрытие по всей серии —
какие темы раскрыты в скольких разговорах, а какие не поднял никто. Можно вести
несколько исследований параллельно и переключаться между ними одним выпадающим списком.

Транскрипт живой: границы реплик ловит потоковый Silero VAD, распознаёт Parakeet TDT —
текст появляется через секунду-другую после того, как человек договорил, а не пачками
раз в полминуты. Parakeet работает на CPU, поэтому вся видеопамять остаётся у LLM;
Whisper остался переключаемой опцией (`asr.backend`) для словаря терминов и языков
вне 25 европейских.

**Приватность: всё работает локально.** Аудио, транскрипты и гайд никуда не отправляются —
ASR (Parakeet или Whisper) и LLM (Ollama) крутятся на вашей машине, веб-сервер слушает
только 127.0.0.1, интерфейс не загружает никаких внешних ресурсов, телеметрии нет.
Сеть нужна один раз — скачать веса моделей при установке. Запись интервью и транскрипт
остаются на диске рядом с проектом: аудио пишется в `audio.wav` в папке сессии
(`storage.save_audio: false` — если хранить голос не нужно).

Документация: [PLAN.md](PLAN.md) — исходный план и бюджеты памяти;
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — устройство системы, API и точки
расширения; [docs/TESTING.md](docs/TESTING.md) — план тестирования с ручными
чек-листами и критериями приёмки.

## Требования

| | macOS | Windows |
|---|---|---|
| Железо | Apple Silicon (M4+), 32 GB | NVIDIA RTX 4070 Super (12 GB VRAM), 32 GB RAM |
| ОС | macOS 14+ | Windows 10 22H2+ / Windows 11 |
| Python | 3.11+ | 3.11+ |
| Захват системного звука | [BlackHole 2ch](https://existential.audio/blackhole/) | WASAPI loopback — ставить нечего |
| LLM-сервер | [Ollama](https://ollama.com) | [Ollama](https://ollama.com) |

Наушники обязательны: если звук респондента идёт из колонок, микрофон подхватит его,
и реплики продублируются в канале интервьюера.

## Установка

### 0. Самый короткий путь — ярлык

Двойной клик по **`Launch ILH.lnk`** в корне репозитория. Ярлык — единственное,
что нужно нажимать в обычной жизни: при первом запуске он сам вызовет `setup.py`
(окружение, зависимости, веса ASR, Ollama), а дальше просто поднимает приложение.

Как это устроено: ярлык указывает на `tools/launch_win.bat`, тот передаёт работу
своей же скрытой копии — она и владеет процессом приложения, — а видимое окно
показывает стадии запуска и закрывается само, как только приложение ответило на
своём порту. Если приложение не поднялось за 120 с, окно останется открытым с
путями к логам и хвостом `logs/launcher-runner.log`.

Приложение уже запущено — ярлык не поднимает второй экземпляр: он говорит об этом
и открывает вкладку браузера на тот же адрес (окно легко теряется за Zoom).

Посмотреть падение живьём, не в логах:

```powershell
set ILH_DIAGNOSTIC_LAUNCH=1 && tools\launch_win.bat
```

Ярлык хранит и относительный путь, поэтому переживает перенос папки. Если он всё
же потерялся — пересоздать (`-Desktop` положит копию ещё и на рабочий стол):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make_shortcut.ps1
```

На macOS/Linux ярлыков нет — тот же сценарий даёт `tools/launch_mac.command`
(двойной клик в Finder; при первом запуске так же вызывает `setup.py`). Если
репозиторий приехал с Windows, бит запуска придётся вернуть один раз руками:

```bash
chmod +x tools/launch_mac.command tools/reset_mac.command
```

Всё, что ниже, — ручной путь и подробности того, что делает ярлык.

### 1. Python-окружение

Быстрый путь — скрипт установки `setup.py`, один на все платформы:

```bash
python3 setup.py    # macOS / Linux
```
```powershell
python setup.py     # Windows
```

Он создаёт `.venv`, ставит зависимости под вашу ОС, качает веса ASR, а затем
предлагает доставить внешние компоненты — каждый спрашивает отдельно:

| Компонент | macOS | Windows |
|---|---|---|
| Ollama | `brew install --cask ollama` | `winget install Ollama.Ollama` |
| Модель LLM | `ollama pull` (имя берётся из `config.json`) | то же |
| Системный звук | `brew install blackhole-2ch` | не требуется — WASAPI loopback |

Сервер Ollama скрипт поднимает сам, так что после установки шаг 2 можно пропустить.
На Windows шаг 3 тоже не нужен: системный звук берётся прямо с устройства вывода.

Если что-то не доехало, доскачать можно и из самого приложения: при запуске оно
показывает мастер с прогрессом (**⚙ Настройки приложения** → строка «Модели» → ⤓).

Флаги: `-y` / `--yes` (ставить всё без вопросов), `--no-extras` (только Python-окружение,
не трогать Ollama и кабель), `--recreate` (пересоздать `.venv`), `--skip-model`
(не качать веса ASR), `--requirements <файл>` (свой набор зависимостей).
Скрипт идемпотентен: повторный запуск ничего не ломает и работает как проверка окружения.

Вручную то же самое:

```bash
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements-macos.txt    # или -windows.txt / -common.txt (Linux)
python -m tools.fetch_asr_model
```

На Windows свежий драйвер NVIDIA нужен, только если вы переключитесь на Whisper
(`asr.backend: faster`) — Parakeet по умолчанию работает на CPU. CUDA Toolkit
ставить не нужно: cuBLAS/cuDNN приезжают pip-пакетами, приложение само подключает
их DLL. Если CUDA недоступна, Whisper откатится на CPU.

### 2. Ollama и модель

Если `setup.py` уже поставил Ollama и модель — этот шаг пропускайте. Вручную:

1. Установите Ollama с [ollama.com](https://ollama.com) и запустите её.
2. Скачайте модель:
   ```bash
   ollama pull qwen3:8b
   ```

Опциональный тюнинг (экономия VRAM, особенно на Windows) — переменные окружения
для Ollama: `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0`.

### 3. Системный звук (канал респондента)

Разделение говорящих делается на уровне ОС: микрофон = интервьюер, системный звук
(выход Zoom) = респондент.

#### Windows — ничего ставить не нужно

Системный звук берётся прямо с устройства вывода через WASAPI loopback
(см. [app/audio/loopback.py](app/audio/loopback.py)). В приложении выберите в поле
«Системный звук» свои наушники — те же, в которые играет Zoom. Ни VB-Cable, ни
настройка Zoom, ни «Прослушивать с данного устройства» не нужны.

Пункт «(WASAPI loopback)» в списке устройств — это и есть нужный вход; приложение
подставляет текущее устройство вывода само. VB-Cable по-прежнему поддерживается:
если он установлен, его можно выбрать в том же списке (см. ниже).

#### macOS — BlackHole + Multi-Output Device

На macOS аналога loopback без нативного кода нет, поэтому виртуальное устройство
пока нужно:

1. Установите BlackHole 2ch: `brew install blackhole-2ch` (или инсталлятором с сайта),
   перезагрузитесь при необходимости.
2. Откройте **Audio MIDI Setup** (Настройка Audio-MIDI).
3. Кнопкой «+» внизу слева создайте **Multi-Output Device** и отметьте в нём:
   - ваши наушники/динамики (галочка первой строкой),
   - **BlackHole 2ch**.
4. В **Zoom → Settings → Audio → Speaker** выберите созданный **Multi-Output Device**.
   Теперь вы слышите респондента в наушниках, и та же дорожка идёт в BlackHole.
5. В приложении: «Системный звук» = **BlackHole 2ch**, «Микрофон» = ваш микрофон
   (тот же, что выбран в Zoom как Microphone).

#### Windows — VB-Cable (запасной путь)

Нужен, только если loopback почему-то недоступен (например, не встал
`PyAudioWPatch`).

1. Установите VB-Cable (распаковать, правой кнопкой на `VBCABLE_Setup_x64.exe` →
   запустить от администратора), перезагрузитесь.
2. В **Zoom → Settings → Audio → Speaker** выберите **CABLE Input (VB-Audio Virtual Cable)**.
3. Чтобы слышать респондента: **Параметры звука Windows → Панель управления звуком →
   вкладка «Запись» → CABLE Output → Свойства → вкладка «Прослушать»** → включите
   **«Прослушивать с данного устройства»** и выберите свои наушники. (Появляется небольшая
   задержка монитора — это нормально.)
4. В приложении: «Системный звук» = **CABLE Output (VB-Audio Virtual Cable)**,
   «Микрофон» = ваш микрофон.

## Запуск

```bash
python -m app.main            # окно в правой половине экрана, поверх других окон
python -m app.main --browser  # то же в обычной вкладке браузера
```

Окно стартует компактным (чтобы не закрывать собой Zoom), но **тянется за край**:
растянутый размер запоминается и применяется при следующем запуске. Стартовый
размер, минимум и «поверх остальных» настраиваются в блоке `window` конфига.

Если моделей не хватает, приложение при запуске само предложит их скачать и покажет
прогресс — терминал не нужен. То же окно открывается из **⚙ Настройки приложения** →
строка «Модели» → ⤓.

Из консоли то же самое:

```bash
python -m tools.fetch_asr_model    # Parakeet, ~670 МБ в кэш HuggingFace; дальше офлайн
```

### Порядок работы

0. Приложение открывается **списком проектов**. Карточка показывает число записанных
   интервью, дату последнего и длительность; клик открывает проект, «⋯» — папку,
   переименование и удаление. Проект помнит гайд, словарь и длительность и складывает
   свои интервью в собственную папку — так утренняя серия и вечерняя не путаются.
   Кнопка **«Записать без проекта»** — для разового интервью, оно уйдёт в общий
   `sessions/`. Строка сверху показывает готовность (микрофон, системный звук,
   модели, LLM) — чинить лучше здесь, а не за минуту до созвона.
   Вернуться к списку из проекта — кнопкой **←** в шапке.
   Настроек две, и делятся они по владельцу: **⚙ «Настройки приложения»** —
   общее на машину (тема, LLM, модели, устройства, промпты анализа), вкладка
   **«Настройки проекта»** — то, что меняется от исследования к исследованию
   (длительность, гайд, доп. инструкции, словарь терминов).
1. Откройте **⚙** и проверьте индикатор LLM (должно быть «✓ Ollama…»).
2. Там же выберите **микрофон** и **системный звук** (на Windows подставляется loopback текущего
   устройства вывода, на macOS — BlackHole). Под каждым устройством — **полоска уровня**: скажите фразу и включите
   тестовый звук в Zoom — обе должны дёргаться. Это главная страховка от «пустого канала».
   Полоски живут в этом диалоге: пока он открыт, звук слушается и до старта сессии.
3. Вкладка **«Настройки проекта»**. Гайд: возьмите из **библиотеки** (если уже
   парсили) или вставьте текст →
   **«Распарсить гайд»** → проверьте структуру → **«Использовать эту структуру»**
   (гайд сохранится в библиотеку; ✕ рядом с библиотекой удаляет гайд и сначала
   спрашивает подтверждение). Задайте **длительность интервью** и, по желанию,
   **словарь терминов** (названия продукта, бренды, жаргон). Внимание: словарь
   работает только с Whisper (`asr.backend: faster` или `mlx`) — Parakeet, стоящий
   по умолчанию, подсказку промптом не поддерживает и предупредит об этом в шапке.
4. **Старт**. В шапке пойдёт таймер до следующего анализа (по умолчанию 4 минуты);
   кнопка **«Анализ»** запускает цикл немедленно.
5. Во время интервью основная вкладка — **Интервью**: слева гайд ровно тем текстом,
   который вы вставили (кнопки A−/A+ меняют кегль), справа две колонки. Клик по
   вопросу делает его текущим; комментарий, отправленный по ⏎, сохраняется с
   отметкой времени и с этим вопросом — в `flags.jsonl` и в `transcript.md`.
   Нижняя колонка — «спросить дополнительно»: записали по ходу, задали, поставили
   галочку; список уезжает в отчёт. Яркий момент без текста — кнопка 🚩 или
   клавиша **F5**.
   Сверху той же колонки — **подсказки LLM**: строка темпа, пробинг-вопросы (🔍)
   по свежим репликам и непокрытые темы с готовыми формулировками (⧉ копирует
   вопрос, ✕ скрывает подсказку по теме). Анализ приходит раз в несколько минут,
   когда разговор уже ушёл вперёд, поэтому каждая карточка подписана «раздел →
   вопрос», новые несколько секунд подсвечены, а клик по карточке возвращает гайд
   к нужному вопросу. Если канал перестал получать звук (отвалились наушники),
   приложение предупредит и попробует переоткрыть устройство.
   С LLM можно спорить: во вкладке **Темы** клик по теме помечает её покрытой
   вручную (✔ — LLM больше её не трогает), повторный клик снимает метку.
6. **Стоп** — приложение дораспознаёт хвост аудио, делает финальную сверку всего
   транскрипта с гайдом и собирает отчёт (может занять пару минут — статус виден в шапке).
7. Вкладка **Проект** — взгляд на серию целиком: список записанных интервью
   (дата, длительность, покрытие, 📂 открывает папку) и **сводное покрытие**: в
   скольких интервью тема раскрыта. Тема, которую не поднял никто, светится
   красным — это и есть повод поправить гайд к следующему разговору.
   **🎧 открывает расшифровку прошлого интервью вместе с записью**: реплики с
   таймкодами и флаги одной лентой, плеер сверху, клик по строке проматывает
   запись на этот момент и подсвечивает звучащую реплику. Если аудио не
   сохранялось, иконка 📄 — остаётся один текст.

### Проекты

Проект — серия интервью по одному гайду. Он держит пресет и свои сессии:

```
projects/онбординг-b2b-весна/
  project.json                  — гайд, словарь ASR, длительность, доп. инструкции
  sessions/2026-08-08_10-15-00/ — обычная папка сессии (таблица ниже)
```

Пресет догоняет реальность сам: с чем вошли в интервью — то проект и запомнит,
отдельной кнопки «сохранить» нет. Выбранный проект переживает перезапуск.
Удалить через интерфейс можно только пустой проект — папку с записанными
интервью приложение не трогает, это делается руками.

### Что приложение спрашивает у модели

Во вкладке **«Настройки проекта»** есть поле **доп. инструкций** — контекст именно этой серии:
кто респонденты, на что смотреть особенно внимательно, чего не предлагать
(«респонденты — врачи», «не предлагай вопросы про цену — их задаёт другая
команда»). Инструкции добавляются к промптам анализа всех интервью проекта.

Если этого мало, сами промпты открыты: **⚙ → Промпты анализа** показывает
четыре текста, которые уходят в модель — цикл во время интервью, правило
пробинг-вопросов, финальная сверка на «Стоп» и разбор текста гайда. Их можно
переписать под своё исследование; у каждого есть «Вернуть дефолт».

Подстановки в фигурных скобках (`{guide_block}` — сам гайд, `{probes_rule}` —
правило проб) заполняет приложение, и удалить их нельзя: такую правку оно не
примет и объяснит, чего не хватает. Правки лежат в `prompts.json` рядом с
`config.json` и применяются к следующему запущенному интервью — начатая сессия
доигрывает по тем промптам, с которыми стартовала.

### Что сохраняется

`projects/<проект>/sessions/2026-07-11_14-30-00/` (или `sessions/…` без проекта):

| Файл | Что это |
|---|---|
| `transcript.jsonl` | сегменты с говорящим и таймштампами (append по ходу — переживает сбой) |
| `transcript.md` | читаемый транскрипт |
| `audio.wav` | запись интервью: стерео 16 kHz, слева интервьюер, справа респондент (≈230 МБ/час; `storage.save_audio: false` отключает) |
| `guide.json` | подтверждённая структура гайда |
| `coverage_state.json` | финальное состояние покрытия |
| `recommendations.jsonl` | история рекомендаций по циклам |
| `report.md` | отчёт: резюме, тезисы по темам, непокрытое, флаги |
| `flags.jsonl` | отмеченные моменты |
| `analysis_log.jsonl` | сырые обмены с LLM (для отладки) |
| `meta.json` | параметры сессии |

Библиотека гайдов лежит отдельно, в `guides/`.

### Сброс

Вернуть рабочую копию в состояние «как из репозитория»:

```powershell
tools\reset_win.bat
```
```bash
tools/reset_mac.command
```

Скрипт останавливает приложение и сносит всё в корне, чего нет в исходниках:
`.venv`, `logs/`, `sessions/`, `guides/`, `config.json`, кэши. Перед вопросом он
печатает точный список того, что удалит; продолжает только по ответу `Yes` —
любой другой ввод (и пустой) отменяет.

Гасится при этом только *свой* Python: сначала PID из `logs/launcher.pid` (и то
после сверки, что процесс всё ещё принадлежит этой папке — PID'ы переиспользуются),
затем `python.exe`/`pythonw.exe`, чей командный запуск ведёт из этого каталога.
Чужой Python — Jupyter, другие проекты — не трогается.

Что переживает сброс: исходники, история git, а также веса ASR (кэш HuggingFace)
и модели Ollama — они лежат вне репозитория, и качать их заново незачем.

Флаг `--keep-venv` сохраняет `.venv`: цикл «сбросил — запустил» становится
секундным вместо минутного. Но лончер вызывает `setup.py`, только когда `.venv`
нет, — то есть с этим флагом первый запуск не проверяется. Перед проверкой релиза
запускайте без него.

## Конфигурация

Скопируйте `config.example.json` в `config.json` и меняйте нужное. Основное:

- `analysis.interval_s` — период анализа (по умолчанию 240 с);
- `analysis.reconcile_every` — каждый N-й цикл перепроверяет окно с прошлой сверки (0 — выкл);
- `analysis.max_probes` — пробинг-вопросов за цикл (0 — отключить пробинг);
- `analysis.final_sweep` / `analysis.report` — финальная сверка и отчёт на «Стоп»;
- `llm.model` — любая модель Ollama; на M4 Pro/Max можно `qwen3:14b`;
- `asr.backend` — `auto` (Parakeet) / `parakeet` / `mlx` / `faster` / `faster-cpu`;
- `asr.parakeet_model` — любая модель onnx-asr; для интервью целиком на русском
  можно попробовать `gigaam-v2-rnnt` (специализирована под русский, но смешанную
  RU/EN речь не потянет);
- `audio.vad_redemption_s` — сколько тишины считать концом реплики (0.6 с). Меньше —
  транскрипт быстрее, но фразы чаще рвутся на паузах внутри мысли;
- `audio.max_chunk_s` — потолок для монолога: длинный ответ принудительно режется,
  чтобы транскрипт не молчал до самого конца;
- `audio.vad` — `auto` (потоковый Silero) / `energy-stream` / `silero` / `energy`;
  последние два — исходная батчевая нарезка по паузам, запасной путь;
- `llm.num_ctx` — уменьшите до 6144, если VRAM впритык;
- `storage.save_audio` — писать ли `audio.wav` в папку сессии (по умолчанию да);
- `storage.sessions_dir` — куда складывать сессии вне проектов;
- `storage.projects_dir` — где живут проекты вместе со своими сессиями;
- `window.width` / `window.height` — размер окна при первом запуске (дальше
  запоминается растянутый; `window.remember_size: false` отключает);
- `window.min_width` / `window.min_height` — насколько окно даёт себя сжать;
- `window.on_top` — держать окно поверх остальных (по умолчанию да).

### VRAM

Parakeet работает на CPU (`asr.providers: ["CPUExecutionProvider"]`) и **не занимает
VRAM вообще** — она целиком достаётся LLM. Так что на 12 GB лестница деградации
почти не нужна: при нехватке хватает KV-кэша `q8_0` (env-переменные Ollama выше) и
`llm.num_ctx: 6144`.

Менять провайдер на `CUDAExecutionProvider` не стоит без замера: fp32-энкодер займёт
на GPU больше, чем занимал Whisper, а `onnxruntime-gpu` конфликтует с CPU-сборкой
`onnxruntime`, которую тянет faster-whisper. Если всё же переключаетесь на Whisper
(`asr.backend: faster`), прежняя лестница в силе: `asr.compute_type: int8_float16` →
`llm.num_ctx: 6144` → `llm.model: qwen3:4b-instruct-2507` → `asr.backend: faster-cpu`.

### Apple Silicon

Всё работает без отдельной настройки, но **Metal под Parakeet сейчас не задействован**:
onnx-asr гоняет модель на CPU. Это всё равно кратно быстрее Whisper, однако на Mac
остаётся запас, который пока не выбран. Три варианта, по возрастанию усилий:

1. Как есть — Parakeet на CPU. Ядра M-серии быстрые, для реплик в несколько секунд
   этого достаточно.
2. Попробовать CoreML: `"asr": { "providers": ["CoreMLExecutionProvider", "CPUExecutionProvider"] }`.
   onnxruntime такой провайдер поддерживает, но выигрыш зависит от того, какие слои
   модели на него лягут — обязательно сравните `tools/bench_asr.py` до и после.
3. `mlx-whisper` никуда не делся: `asr.backend: mlx` вернёт прежнее поведение
   (и словарь терминов, которого у Parakeet нет).

Полноценный путь — отдельный бэкенд на `parakeet-mlx` (именно так это сделано в
stenoai): та же модель, но через Metal. Это добавление одного класса и ветки в
`asr/factory.py`, см. «Точки расширения» в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Проверка без интервью

Движок покрытия можно погонять на текстовом транскрипте (нужен только Ollama, без аудио):

```bash
python -m tools.simulate --guide examples/guide.txt --transcript examples/interview.txt --final
```

(`--final` дополнительно прогоняет финальную сверку и печатает тезисы для отчёта.)

Юнит-тесты ядра: `pip install -r requirements-dev.txt && pytest`. Тот же набор
(включая E2E конвейера на фейковых ASR/LLM и API-тесты) гоняется в GitHub Actions
на Linux/macOS/Windows.

Скорость распознавания на своём железе можно померить на любой записи:

```bash
python -m tools.bench_asr запись.wav          # RTF по каждому доступному бэкенду
```

## Безопасность и данные

Приложение работает полностью локально: ни аудио, ни транскрипт, ни разбор
гайда наружу не уходят. Ключей API нет вообще — LLM это локальная Ollama.

**Сетевой периметр.** Сервер слушает только `127.0.0.1` и вдобавок сверяет
заголовки `Host` и `Origin` (`app/server/security.py`). Первое нужно против DNS
rebinding, второе — потому что WebSocket не подчиняется CORS: без проверки любая
открытая во время интервью вкладка могла бы подключиться к `/ws` и читать живой
транскрипт. Настройки — в блоке `security` конфига:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `security.allowed_hosts` | `["127.0.0.1", "localhost", "::1"]` | Допустимые значения `Host` |
| `security.require_origin` | `false` | Требовать `Origin` и от не-браузерных клиентов (curl, скрипты) |

**Данные на диске лежат открытым текстом и не удаляются сами.** В папке проекта
остаются `audio.wav` (около 230 МБ на час записи), `transcript.jsonl` и
`transcript.md`, а также `recommendations.jsonl` с дословными цитатами
респондента. Политики хранения у приложения нет — это осознанно: удалять
исследовательские материалы за исследователя оно не должно. Практические
следствия:

- если запись звука не нужна, выключите её: `storage.save_audio: false` —
  транскрипт и отчёт от неё не зависят;
- папки `projects/`, `sessions/`, `guides/` и `logs/` в `.gitignore`, но на
  резервные копии и синхронизацию облака это не распространяется;
- `logs/app.log` (ротация 2 МБ × 3) текста транскрипта не содержит.

Модель распознавания скачивается с HuggingFace на закреплённом коммите
(`asr.parakeet_revision`), версии зависимостей зафиксированы точно — обновление
на машине исследователя не происходит само по себе.

## Ограничения

- **Языки.** Parakeet покрывает 25 европейских языков (русский и английский среди
  них). Для языков вне этого набора — японского, китайского, корейского, арабского —
  переключайтесь на Whisper: `asr.backend: faster`.
- **Переключение языка внутри фразы** остаётся шумным местом; реплики целиком на RU
  или EN распознаются нормально.
- **Словарь терминов** работает только с Whisper — см. «Конфигурация».
- Задержка транскрипта складывается из `audio.vad_redemption_s` (0.6 с),
  `audio.poll_interval_s` (0.2 с) и времени декодирования. Вклад самого
  конвейера замерен на записи реальной речи, подаваемой в реальном темпе:
  **0.65–0.80 с** от конца реплики до строки в транскрипте. Сверху ляжет
  декодирование — оно зависит от машины, померьте `tools/bench_asr.py`.
  Внутри длинного монолога первый кусок придёт не раньше `audio.max_chunk_s`.
- Always-on-top работает только в режиме окна (pywebview). С `--browser` вкладка будет
  прятаться за Zoom. На Windows для окна нужен WebView2 Runtime (в Windows 11 есть
  из коробки).
- Гайд разумного размера (до ~40 тем): весь гайд + состояние + дельта должны помещаться
  в контекст LLM.
- Эхоподавления нет — работайте в наушниках.
- Если у собеседников совпадают устройства (микрофон = системный звук), приложение
  не даст стартовать.

## Устранение неполадок

| Симптом | Что делать |
|---|---|
| «Ollama не отвечает» | Запустите приложение Ollama / `ollama serve`; проверьте `llm.base_url` |
| «Модель не найдена» | `ollama pull qwen3:8b` (имя должно совпадать с `llm.model`) |
| Долгая пауза при первом старте | Не скачаны веса ASR: `python -m tools.fetch_asr_model` |
| «Словарь терминов проигнорирован» в шапке | Parakeet не умеет подсказку промптом. Нужен словарь — `asr.backend: faster` |
| Транскрипт пустой, хотя полоски уровня дёргаются | Смотрите `logs/app.log`: если там «VAD: энергетический», Silero не загрузился (проверьте `onnxruntime` и `app/audio/data/silero_vad.onnx`) |
| Реплики рвутся на середине фразы | Увеличьте `audio.vad_redemption_s` (например до 1.0) |
| faster-whisper не видит CUDA | Обновите драйвер NVIDIA; проверьте, что стоят pip-пакеты `nvidia-cublas-cu12`, `nvidia-cudnn-cu12`; смотрите `logs/app.log` — при неудаче ASR сам уйдёт на CPU |
| Не открывается аудиоустройство | Проверьте разрешение на микрофон (macOS: Системные настройки → Конфиденциальность → Микрофон; терминалу/IDE тоже нужно разрешение) |
| В канале респондента тишина | Windows: «Системный звук» должен быть тем устройством вывода, в которое реально играет Zoom (ищите пункт с пометкой WASAPI loopback). macOS: Zoom должен выводить звук в BlackHole (см. настройку выше); проверьте, что в Zoom не включён «оригинальный звук» на другое устройство |
| В списке нет пунктов «(WASAPI loopback)» | Windows: не установлен `PyAudioWPatch` — `pip install -r requirements-windows.txt`. Запасной путь — VB-Cable |
| Окно не появляется (Windows) | Установите [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) или запустите с `--browser` |
| Анализ дольше пары минут | Модель не влезла в VRAM и уехала на CPU — пройдите лестницу деградации из раздела «Конфигурация» |

Логи: `logs/app.log`.
