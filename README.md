# Interviewer's Little Helper

Локальный ассистент для качественных интервью по Zoom: в реальном времени расшифровывает
речь интервьюера и респондента в раздельные транскрипты, раз в 4 минуты сравнивает разговор
с гайдом исследования через локальную LLM и показывает в компактном окне 600×400 (поверх Zoom):

- **чеклист покрытия тем** — covered / partial / not_covered;
- **подсказки** — какие темы пропущены и готовые формулировки вопросов;
- **пробинг-вопросы** — уточнения по интересным свежим репликам респондента;
- **темп интервью** — успеваете ли пройти гайд за отведённое время;
- живой транскрипт с **флагами** (клавиша F — отметить яркий момент).

Точность держат сверочные проходы: каждый 4-й цикл перепроверяет последние минуты разговора
(ловит темы, пропущенные в отдельных циклах), а на «Стоп» весь транскрипт прогоняется целиком.
После сессии на диске: транскрипт (JSONL + Markdown), состояние покрытия, история рекомендаций
и **отчёт** — резюме, тезисы по темам, непокрытое, отмеченные моменты. Гайды сохраняются в
**библиотеку** и переиспользуются между интервью серии.

Транскрипт живой: границы реплик ловит потоковый Silero VAD, распознаёт Parakeet TDT —
текст появляется через секунду-другую после того, как человек договорил, а не пачками
раз в полминуты. Parakeet работает на CPU, поэтому вся видеопамять остаётся у LLM;
Whisper остался переключаемой опцией (`asr.backend`) для словаря терминов и языков
вне 25 европейских.

**Приватность: всё работает локально.** Аудио, транскрипты и гайд никуда не отправляются —
ASR (Parakeet или Whisper) и LLM (Ollama) крутятся на вашей машине, веб-сервер слушает
только 127.0.0.1, интерфейс не загружает никаких внешних ресурсов, телеметрии нет.
Сеть нужна один раз — скачать веса моделей при установке.

Документация: [PLAN.md](PLAN.md) — исходный план и бюджеты памяти;
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — устройство системы, API и точки
расширения; [docs/TESTING.md](docs/TESTING.md) — план тестирования с ручными
чек-листами и критериями приёмки.

## Требования

| | macOS | Windows |
|---|---|---|
| Железо | Apple Silicon (M4+), 32 GB | NVIDIA RTX 4070 Super (12 GB VRAM), 32 GB RAM |
| ОС | macOS 14+ | Windows 10 22H2+ / Windows 11 |
| Python | 3.11+ | 3.11+ |
| Виртуальный аудиокабель | [BlackHole 2ch](https://existential.audio/blackhole/) | [VB-Cable](https://vb-audio.com/Cable/) |
| LLM-сервер | [Ollama](https://ollama.com) | [Ollama](https://ollama.com) |

Наушники обязательны: если звук респондента идёт из колонок, микрофон подхватит его,
и реплики продублируются в канале интервьюера.

## Установка

### 1. Python-окружение

Один скрипт на все платформы: создаёт `.venv`, ставит зависимости под вашу ОС,
качает веса ASR и проверяет Ollama с виртуальным аудиокабелем.

```bash
python3 install.py     # macOS / Linux
python install.py      # Windows
```

Полезные флаги: `--no-model` (не качать веса сейчас), `--venv ПУТЬ`.
Повторный запуск переиспользует существующее окружение, так что скриптом же
удобно доставлять обновления зависимостей.

Вручную то же самое:

```bash
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements-macos.txt    # или -windows.txt / -common.txt (Linux)
python -m tools.fetch_asr_model
```

На Windows свежий драйвер NVIDIA нужен, только если вы переключитесь на Whisper
(`asr.backend: faster`) — Parakeet по умолчанию работает на CPU. CUDA Toolkit
ставить не нужно: cuBLAS/cuDNN приезжают pip-пакетами, приложение само подключает
их DLL. Если CUDA недоступна, Whisper откатится на CPU.

### 2. Ollama и модель

1. Установите Ollama с [ollama.com](https://ollama.com) и запустите её.
2. Скачайте модель:
   ```bash
   ollama pull qwen3:8b
   ```

Опциональный тюнинг (экономия VRAM, особенно на Windows) — переменные окружения
для Ollama: `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0`.

### 3. Виртуальное аудиоустройство

Разделение говорящих делается на уровне ОС: микрофон = интервьюер, системный звук
(выход Zoom) = респондент. Для захвата системного звука нужен виртуальный кабель.

#### macOS — BlackHole + Multi-Output Device

1. Установите BlackHole 2ch: `brew install blackhole-2ch` (или инсталлятором с сайта),
   перезагрузитесь при необходимости.
2. Откройте **Audio MIDI Setup** (Настройка Audio-MIDI).
3. Кнопкой «+» внизу слева создайте **Multi-Output Device** и отметьте в нём:
   - ваши наушники/динамики (галочка первой строкой),
   - **BlackHole 2ch**.
4. В **Zoom → Settings → Audio → Speaker** выберите созданный **Multi-Output Device**.
   Теперь вы слышите респондента в наушниках, и та же дорожка идёт в BlackHole.
5. В приложении: «Системный звук» = **BlackHole 2ch**, «Микрофон» = ваш микрофон
   (тот же, что выбран в Zoom как Microphone).

#### Windows — VB-Cable

1. Установите VB-Cable (распаковать, правой кнопкой на `VBCABLE_Setup_x64.exe` →
   запустить от администратора), перезагрузитесь.
2. В **Zoom → Settings → Audio → Speaker** выберите **CABLE Input (VB-Audio Virtual Cable)**.
3. Чтобы слышать респондента: **Параметры звука Windows → Панель управления звуком →
   вкладка «Запись» → CABLE Output → Свойства → вкладка «Прослушать»** → включите
   **«Прослушивать с данного устройства»** и выберите свои наушники. (Появляется небольшая
   задержка монитора — это нормально.)
4. В приложении: «Системный звук» = **CABLE Output (VB-Audio Virtual Cable)**,
   «Микрофон» = ваш микрофон.

## Запуск

```bash
python -m app.main            # окно 600×400 поверх других окон
python -m app.main --browser  # то же в обычной вкладке браузера
```

Веса ASR скачивает скрипт установки. Если вы ставили зависимости вручную, сделайте это
до первого интервью — иначе первый старт сессии уйдёт на загрузку:

```bash
python -m tools.fetch_asr_model    # Parakeet, ~670 МБ в кэш HuggingFace; дальше офлайн
```

### Порядок работы

1. Вкладка **Настройка**: проверьте индикатор LLM (должно быть «✓ Ollama…»).
2. Выберите **микрофон** и **системный звук** (BlackHole / CABLE Output подсвечиваются
   автоматически). Под каждым устройством — **полоска уровня**: скажите фразу и включите
   тестовый звук в Zoom — обе должны дёргаться. Это главная страховка от «пустого канала».
3. Гайд: возьмите из **библиотеки** (если уже парсили) или вставьте текст →
   **«Распарсить гайд»** → проверьте структуру → **«Использовать эту структуру»**
   (гайд сохранится в библиотеку). Задайте **длительность интервью** и, по желанию,
   **словарь терминов** (названия продукта, бренды, жаргон). Внимание: словарь
   работает только с Whisper (`asr.backend: faster` или `mlx`) — Parakeet, стоящий
   по умолчанию, подсказку промптом не поддерживает и предупредит об этом в шапке.
4. **Старт**. В шапке пойдёт таймер до следующего анализа (по умолчанию 4 минуты);
   кнопка **«Анализ»** запускает цикл немедленно.
5. Во время интервью держите открытой вкладку **Подсказки**: сверху — строка темпа,
   пробинг-вопросы (🔍) по свежим репликам, затем непокрытые темы с готовыми
   формулировками (⧉ копирует вопрос, ✕ скрывает подсказку по теме). Яркий момент —
   кнопка 🚩 или клавиша **F**. Если канал перестал получать звук (отвалились
   наушники), приложение предупредит и попробует переоткрыть устройство.
   С LLM можно спорить: во вкладке **Темы** клик по теме помечает её покрытой
   вручную (✔ — LLM больше её не трогает), повторный клик снимает метку.
6. **Стоп** — приложение дораспознаёт хвост аудио, делает финальную сверку всего
   транскрипта с гайдом и собирает отчёт (может занять пару минут — статус виден в шапке).

### Что сохраняется

`sessions/2026-07-11_14-30-00/`:

| Файл | Что это |
|---|---|
| `transcript.jsonl` | сегменты с говорящим и таймштампами (append по ходу — переживает сбой) |
| `transcript.md` | читаемый транскрипт |
| `guide.json` | подтверждённая структура гайда |
| `coverage_state.json` | финальное состояние покрытия |
| `recommendations.jsonl` | история рекомендаций по циклам |
| `report.md` | отчёт: резюме, тезисы по темам, непокрытое, флаги |
| `flags.jsonl` | отмеченные моменты |
| `analysis_log.jsonl` | сырые обмены с LLM (для отладки) |
| `meta.json` | параметры сессии |

Библиотека гайдов лежит отдельно, в `guides/`.

## Конфигурация

Скопируйте `config.example.json` в `config.json` и меняйте нужное. Основное:

- `analysis.interval_s` — период анализа (по умолчанию 240 с);
- `analysis.reconcile_every` — каждый N-й цикл перепроверяет окно с прошлой сверки (0 — выкл);
- `analysis.max_probes` — пробинг-вопросов за цикл (0 — отключить пробинг);
- `analysis.final_sweep` / `analysis.report` — финальная сверка и отчёт на «Стоп»;
- `llm.model` — любая модель Ollama; на M4 Pro/Max можно `qwen3:14b`;
- `asr.backend` — `auto` (Parakeet) / `parakeet` / `mlx` / `faster` / `faster-cpu`;
- `asr.parakeet_model` — любая модель onnx-asr; для интервью целиком на русском
  можно попробовать `gigaam-v2-rnnt` (специализирована под русский, но смешанную
  RU/EN речь не потянет);
- `audio.vad_redemption_s` — сколько тишины считать концом реплики (0.6 с). Меньше —
  транскрипт быстрее, но фразы чаще рвутся на паузах внутри мысли;
- `audio.max_chunk_s` — потолок для монолога: длинный ответ принудительно режется,
  чтобы транскрипт не молчал до самого конца;
- `audio.vad` — `auto` (потоковый Silero) / `energy-stream` / `silero` / `energy`;
  последние два — исходная батчевая нарезка по паузам, запасной путь;
- `llm.num_ctx` — уменьшите до 6144, если VRAM впритык;
- `storage.sessions_dir` — куда складывать сессии.

### VRAM

Parakeet работает на CPU (`asr.providers: ["CPUExecutionProvider"]`) и **не занимает
VRAM вообще** — она целиком достаётся LLM. Так что на 12 GB лестница деградации
почти не нужна: при нехватке хватает KV-кэша `q8_0` (env-переменные Ollama выше) и
`llm.num_ctx: 6144`.

Менять провайдер на `CUDAExecutionProvider` не стоит без замера: fp32-энкодер займёт
на GPU больше, чем занимал Whisper, а `onnxruntime-gpu` конфликтует с CPU-сборкой
`onnxruntime`, которую тянет faster-whisper. Если всё же переключаетесь на Whisper
(`asr.backend: faster`), прежняя лестница в силе: `asr.compute_type: int8_float16` →
`llm.num_ctx: 6144` → `llm.model: qwen3:4b-instruct-2507` → `asr.backend: faster-cpu`.

### Apple Silicon

Всё работает без отдельной настройки, но **Metal под Parakeet сейчас не задействован**:
onnx-asr гоняет модель на CPU. Это всё равно кратно быстрее Whisper, однако на Mac
остаётся запас, который пока не выбран. Три варианта, по возрастанию усилий:

1. Как есть — Parakeet на CPU. Ядра M-серии быстрые, для реплик в несколько секунд
   этого достаточно.
2. Попробовать CoreML: `"asr": { "providers": ["CoreMLExecutionProvider", "CPUExecutionProvider"] }`.
   onnxruntime такой провайдер поддерживает, но выигрыш зависит от того, какие слои
   модели на него лягут — обязательно сравните `tools/bench_asr.py` до и после.
3. `mlx-whisper` никуда не делся: `asr.backend: mlx` вернёт прежнее поведение
   (и словарь терминов, которого у Parakeet нет).

Полноценный путь — отдельный бэкенд на `parakeet-mlx` (именно так это сделано в
stenoai): та же модель, но через Metal. Это добавление одного класса и ветки в
`asr/factory.py`, см. «Точки расширения» в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Проверка без интервью

Движок покрытия можно погонять на текстовом транскрипте (нужен только Ollama, без аудио):

```bash
python -m tools.simulate --guide examples/guide.txt --transcript examples/interview.txt --final
```

(`--final` дополнительно прогоняет финальную сверку и печатает тезисы для отчёта.)

Юнит-тесты ядра: `pip install -r requirements-dev.txt && pytest`. Тот же набор
(включая E2E конвейера на фейковых ASR/LLM и API-тесты) гоняется в GitHub Actions
на Linux/macOS/Windows.

Скорость распознавания на своём железе можно померить на любой записи:

```bash
python -m tools.bench_asr запись.wav          # RTF по каждому доступному бэкенду
```

## Ограничения

- **Языки.** Parakeet покрывает 25 европейских языков (русский и английский среди
  них). Для языков вне этого набора — японского, китайского, корейского, арабского —
  переключайтесь на Whisper: `asr.backend: faster`.
- **Переключение языка внутри фразы** остаётся шумным местом; реплики целиком на RU
  или EN распознаются нормально.
- **Словарь терминов** работает только с Whisper — см. «Конфигурация».
- Задержка транскрипта складывается из `audio.vad_redemption_s` (0.6 с),
  `audio.poll_interval_s` (0.2 с) и времени декодирования. Вклад самого
  конвейера замерен на записи реальной речи, подаваемой в реальном темпе:
  **0.65–0.80 с** от конца реплики до строки в транскрипте. Сверху ляжет
  декодирование — оно зависит от машины, померьте `tools/bench_asr.py`.
  Внутри длинного монолога первый кусок придёт не раньше `audio.max_chunk_s`.
- Always-on-top работает только в режиме окна (pywebview). С `--browser` вкладка будет
  прятаться за Zoom. На Windows для окна нужен WebView2 Runtime (в Windows 11 есть
  из коробки).
- Гайд разумного размера (до ~40 тем): весь гайд + состояние + дельта должны помещаться
  в контекст LLM.
- Эхоподавления нет — работайте в наушниках.
- Если у собеседников совпадают устройства (микрофон = системный звук), приложение
  не даст стартовать.

## Устранение неполадок

| Симптом | Что делать |
|---|---|
| «Ollama не отвечает» | Запустите приложение Ollama / `ollama serve`; проверьте `llm.base_url` |
| «Модель не найдена» | `ollama pull qwen3:8b` (имя должно совпадать с `llm.model`) |
| Долгая пауза при первом старте | Не скачаны веса ASR: `python -m tools.fetch_asr_model` |
| «Словарь терминов проигнорирован» в шапке | Parakeet не умеет подсказку промптом. Нужен словарь — `asr.backend: faster` |
| Транскрипт пустой, хотя полоски уровня дёргаются | Смотрите `logs/app.log`: если там «VAD: энергетический», Silero не загрузился (проверьте `onnxruntime` и `app/audio/data/silero_vad.onnx`) |
| Реплики рвутся на середине фразы | Увеличьте `audio.vad_redemption_s` (например до 1.0) |
| faster-whisper не видит CUDA | Обновите драйвер NVIDIA; проверьте, что стоят pip-пакеты `nvidia-cublas-cu12`, `nvidia-cudnn-cu12`; смотрите `logs/app.log` — при неудаче ASR сам уйдёт на CPU |
| Не открывается аудиоустройство | Проверьте разрешение на микрофон (macOS: Системные настройки → Конфиденциальность → Микрофон; терминалу/IDE тоже нужно разрешение) |
| В канале респондента тишина | Zoom должен выводить звук в BlackHole/CABLE Input (см. настройку выше); проверьте, что в Zoom не включён «оригинальный звук» на другое устройство |
| Окно не появляется (Windows) | Установите [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) или запустите с `--browser` |
| Анализ дольше пары минут | Модель не влезла в VRAM и уехала на CPU — пройдите лестницу деградации из раздела «Конфигурация» |

Логи: `logs/app.log`.
