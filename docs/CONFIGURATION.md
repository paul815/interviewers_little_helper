# Справочник по конфигурации

Все настройки приложения — в одном месте: дефолты живут в
[`app/config.py`](../app/config.py), локальные переопределения — в `config.json`
в корне репозитория.

```bash
cp config.example.json config.json
```

Накладывается только то, что вы написали: остальное берётся из дефолтов.
Неизвестные ключи игнорируются с предупреждением в логе — опечатка не роняет
приложение, но и не применяется молча. Битый JSON тоже не фатален: приложение
пишет ошибку в лог и работает на дефолтах.

Вложенность соблюдается: `{"llm": {"model": "qwen3:14b"}}`, а не `"llm.model"`.

## security

Привязки к `127.0.0.1` мало по двум причинам. WebSocket не подчиняется CORS: любой
открытый во время интервью сайт мог бы подключиться к `/ws` и читать транскрипт в
реальном времени. А DNS rebinding подставляет свой домен, который резолвится в
`127.0.0.1`, и обходит привязку целиком — от этого защищает только проверка
заголовка `Host`.

| Ключ | Дефолт | Смысл |
|---|---|---|
| `security.allowed_hosts` | `["127.0.0.1", "localhost", "::1"]` | Допустимые значения заголовка `Host` |
| `security.require_origin` | `false` | Требовать `Origin` и от небраузерных клиентов (curl, скрипты). По умолчанию их пропускают: браузер `Origin` шлёт всегда, а локальный процесс и так читает `projects/` прямо с диска |

## analysis

| Ключ | Дефолт | Смысл |
|---|---|---|
| `analysis.interval_s` | `240` | Период цикла анализа, секунды |
| `analysis.max_recommendations` | `6` | Потолок подсказок в выдаче |
| `analysis.max_probes` | `2` | Пробинг-вопросов за цикл; `0` полностью выключает пробинг |
| `analysis.reconcile_every` | `4` | Каждый N-й цикл перепроверяет окно с прошлой сверки; `0` — выкл. Ловит темы, пропущенные отдельными дельтами, не раздувая контекст |
| `analysis.final_sweep` | `true` | Финальная сверка всего транскрипта на «Стоп» |
| `analysis.report` | `true` | Сборка `report.md` после сессии |
| `analysis.default_duration_min` | `60` | Длительность по умолчанию — от неё считается строка темпа |
| `analysis.output_language` | `"auto"` | Язык вывода анализа: рекомендаций, доказательств, findings и резюме отчёта. `auto` следует языку самого гайда (как он определён при разборе). Любое другое значение уходит в модель дословно — работают и ISO-код (`"en"`, `"ru"`), и название (`"English"`) |

**Замечание про `interval_s`.** 240 с — компромисс: чаще значит больше вызовов LLM
на разговор, где ещё нечего анализировать; реже — подсказка приходит, когда тема
уже уехала. Кнопка «Анализ» в шапке запускает цикл вручную в любой момент.

## audio

| Ключ | Дефолт | Смысл |
|---|---|---|
| `audio.sample_rate` | `16000` | Частота дискретизации конвейера. ASR-модели ждут именно 16 kHz |
| `audio.ring_seconds` | `120.0` | Глубина кольцевого буфера канала. Drop-oldest: отстающий потребитель теряет старое, а не память |
| `audio.poll_interval_s` | `0.2` | Как часто чанкер забирает аудио из кольца. При потоковом VAD это ещё и гранулярность, с которой вообще замечается конец реплики: значение сильно выше `vad_redemption_s` съело бы весь выигрыш в задержке |
| `audio.max_chunk_s` | `25.0` | Потолок для монолога: длинный ответ принудительно режется, чтобы транскрипт не молчал до самого конца |
| `audio.min_pause_s` | `0.7` | **Только батчевая нарезка** (`vad: silero \| energy`) |
| `audio.min_speech_s` | `0.3` | **Только батчевая нарезка** |
| `audio.pad_s` | `0.2` | Post-pad: хвостовые согласные и вдох |
| `audio.pre_pad_s` | `0.3` | Pre-pad: VAD всегда срабатывает после первого слога |
| `audio.vad` | `"auto"` | `auto` / `silero-stream` / `energy-stream` — потоковая нарезка по событиям речи; `silero` / `energy` — исходная батчевая по паузам (запасной путь) |
| `audio.vad_positive_threshold` | `0.50` | Порог входа в речь |
| `audio.vad_negative_threshold` | `0.35` | Порог выхода — ниже входного: войти в речь труднее, чем остаться в ней (гистерезис против дребезга) |
| `audio.vad_min_speech_s` | `0.25` | Короче этого — щелчок, а не реплика |
| `audio.vad_redemption_s` | `0.6` | Столько тишины считается концом реплики. **Главный рычаг задержки** |
| `audio.watchdog_silence_s` | `12.0` | Нет сэмплов дольше — канал считается мёртвым, UI предупреждает, устройство переоткрывается |
| `audio.highpass_hz` | `80.0` | Фильтр высоких частот на пути к VAD и ASR: постоянная составляющая микрофона, гул вентиляторов, стук по столу. `0` — выключить. **Запись на диске не трогает** |
| `audio.echo_detect` | `true` | Замечать голос респондента, попавший ещё и в микрофон (интервью на колонках вместо наушников). Ничего не удаляет — один раз предупреждает в UI |
| `audio.echo_window_s` | `1.5` | Насколько далеко друг от друга могут начаться две копии одной фразы |
| `audio.echo_jaccard` | `0.6` | Доля общих слов, при которой это одно и то же предложение |
| `audio.echo_min_hits` | `2` | Сколько пар нужно до предупреждения. Одно совпадение — совпадение |

**Фильтр и уровень.** Хайпасс линейно-фазовый (скользящее среднее, вычтенное из
сигнала), задержка — половина окна, 2.8 мс при 80 Гц, и стоит 0.01 % ядра.
Громкость чанка правится отдельно, в `asr.input_target_rms`, и только вверх:
тихий встроенный микрофон подтягивается к уровню гарнитуры, а перегруженный
канал обратно уже не починить. Оба шага — в
[`app/audio/preprocess.py`](../app/audio/preprocess.py).

**`vad_redemption_s` — что за что платит.** Меньше (0.4) — транскрипт быстрее, но
фразы чаще рвутся на паузах внутри мысли. Больше (1.0) — реплики целые, но строка
появляется позже. Дефолт 0.6 выбран под разговорную речь.

|---|---|---|

| `asr.parakeet_quantization` | `"int8"` | `int8` ≈ 670 МБ против ~2.5 ГБ у fp32 |
| `asr.parakeet_revision` | `"auto"` | Ревизия весов: `auto` — коммит из каталога; `""` — главная ветка репозитория (воспроизводимость теряется); 40-символьный sha — этот коммит, что бы ни говорил каталог |
| `asr.providers` | `["CPUExecutionProvider"]` | Провайдеры onnxruntime. **CPU намеренно** — см. ниже |
| `asr.language` | `null` | Чем заполнен вопрос о языке при первом «Старте», пока проект не запомнил свой. Ответ пользователя важнее |
| `asr.model` | `"large-v3-turbo"` | Модель Whisper для бэкенда `faster` / `faster-cpu` |
| `asr.mlx_model` | `"mlx-community/whisper-large-v3-turbo"` | Модель Whisper для бэкенда `mlx` |
| `asr.compute_type` | `"auto"` | Whisper: `auto` → `float16` на CUDA, `int8` на CPU. `int8_float16` экономит VRAM |
| `asr.beam_size` | `1` | Whisper: ширина луча. 1 = greedy, быстрее всего |
| `asr.drop_no_speech_prob` | `0.85` | Whisper: выше этой вероятности «здесь не речь» сегмент выбрасывается |
| `asr.input_target_rms` | `0.05` | К этому RMS подтягивается тихий чанк перед распознаванием (`0` — выключить). Только вверх, с потолком усиления и защитой от клиппинга |
| `asr.vocabulary` | `""` | Термины проекта через запятую → `initial_prompt` Whisper. **Parakeet не поддерживает** и предупредит об этом в шапке |

### Как выбирается модель

Язык интервью, названный на «Старте», переопределяет `asr.parakeet_model` на эту
сессию ([`app/asr/router.py`](../app/asr/router.py)):

```
русский              → gigaam-v3-e2e-rnnt   (227 МБ, с пунктуацией)
25 европейских       → nemo-parakeet-tdt-0.6b-v3 (671 МБ, быстрый дефолт)
всё остальное        → Whisper, с языком, зафиксированным явно
```

Последняя ветка переопределяет даже явно заданный `backend`: Parakeet на
незнакомом языке не падает — он выдаёт беглую бессмыслицу, и Whisper здесь
единственный честный вариант.

Сам `backend` роутер намеренно не трогает в первых двух ветках: на `auto` фабрика
по-прежнему может уехать на Whisper, если onnx-asr не установлен, а
зафиксированный в конфиге бэкенд остаётся зафиксированным.

### Почему CPU

Parakeet в int8 на CPU справляется с запасом, и **вся видеопамять остаётся LLM**.
Перевод на `CUDAExecutionProvider` — это не правка одного ключа: `onnxruntime-gpu`
конфликтует с CPU-сборкой `onnxruntime`, которую тянет faster-whisper, так что это
смена зависимости и отказ от Whisper как опции. Выигрыш при этом неочевиден —
fp32-энкодер занял бы на GPU больше, чем занимал Whisper.

## Рецепты

### VRAM

Parakeet работает на CPU и **не занимает VRAM вообще** — она целиком достаётся
LLM. Поэтому на 12 GB лестница деградации почти не нужна: при нехватке хватает
KV-кэша `q8_0` и урезанного контекста.

```bash
# переменные окружения Ollama
OLLAMA_FLASH_ATTENTION=1
OLLAMA_KV_CACHE_TYPE=q8_0
```
```json
{ "llm": { "num_ctx": 6144 } }
```

Если вы всё же переключились на Whisper (`asr.backend: faster`), прежняя лестница
в силе, по шагам:

1. `asr.compute_type: "int8_float16"`
2. `llm.num_ctx: 6144`
3. `llm.model: "qwen3:4b-instruct-2507"`
4. `asr.backend: "faster-cpu"`

### Apple Silicon

Всё работает без отдельной настройки, но **Metal под Parakeet сейчас не
задействован**: onnx-asr гоняет модель на CPU. Это всё равно кратно быстрее
Whisper, однако запас остаётся. Три варианта, по возрастанию усилий:

1. **Как есть.** Ядра M-серии быстрые, для реплик в несколько секунд достаточно.
2. **Попробовать CoreML:**
   ```json
   { "asr": { "providers": ["CoreMLExecutionProvider", "CPUExecutionProvider"] } }
   ```
   onnxruntime такой провайдер поддерживает, но выигрыш зависит от того, какие
   слои на него лягут — обязательно сравните `tools/bench_asr.py` до и после.
3. **`asr.backend: "mlx"`** вернёт прежнее поведение mlx-whisper (и словарь
   терминов, которого у Parakeet нет).

Полноценный путь — отдельный бэкенд на `parakeet-mlx`: та же модель, но через
Metal. Это добавление одного класса и ветки в `asr/factory.py`, см.
[«Точки расширения»](ARCHITECTURE.md#10-точки-расширения).

### Задержка транскрипта

Складывается из трёх слагаемых:

```
vad_redemption_s (0.6)  +  poll_interval_s (0.2)  +  время декодирования
```

Вклад самого конвейера замерен на записи реальной речи, подаваемой в реальном
темпе: **0.65–0.80 с** от конца реплики до строки в транскрипте. Сверху ложится
декодирование — оно зависит от машины, померьте `tools/bench_asr.py`.

Внутри длинного монолога первый кусок придёт не раньше `audio.max_chunk_s`.

Что можно подкрутить:

| Хочу | Меняю | Плачу |
|---|---|---|
| Быстрее строки | `vad_redemption_s: 0.4` | Фразы чаще рвутся на паузах внутри мысли |
| Целее реплики | `vad_redemption_s: 1.0` | Строка появляется позже |
| Быстрее внутри монолога | `max_chunk_s: 15` | Больше принудительных разрезов |
| Меньше нагрузки на CPU | `poll_interval_s: 0.5` | Съедает выигрыш потокового VAD |
