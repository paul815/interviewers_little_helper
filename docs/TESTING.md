# План тестирования

Три уровня: **автотесты** (без железа, гоняются локально и в CI),
**полуавтоматическая проверка LLM-контура** (`tools/simulate.py`, нужен Ollama)
и **ручной кросс-платформенный план** — то, что принципиально не автоматизируется:
реальный звук, маршрутизация Zoom, качество ASR/LLM, VRAM, окно поверх Zoom.

---

## 1. Автотесты

Запуск: `pip install -r requirements-ci.txt && pytest -q` (полные dev-зависимости —
`requirements-dev.txt`). CI: GitHub Actions, матрица Linux/macOS/Windows,
Python 3.11 (`.github/workflows/ci.yml`).

Карта покрытия:

| Файл | Что проверяет |
|---|---|
| `tests/test_core.py` | устойчивый JSON-парсинг (ограждения, `<think>`, мусор); батчевая нарезка чанков: по паузе, принудительная по 25 c, flush хвоста, чистая тишина; **потоковый VAD**: гистерезис, redemption переживает паузу внутри фразы, отсев коротких щелчков, flush; **потоковая нарезка**: разрез по концу речи, две реплики не перекрываются, принудительный разрез монолога без дублей и дыр, отсутствие дрейфа `t0/t1` на 20 репликах; назначение id гайда; дельта-курсор транскрипта; монотонное слияние; жизненный цикл рекомендаций |
| `tests/test_features.py` | выбор режима delta/reconcile; разбиение транскрипта на окна; пробы (живут один цикл, лимит, отвязка неизвестной темы, не вытесняют gap-подсказки); findings только в final; ручные метки (блокируют LLM, ручное понижение, снятие); dismiss до ручного изменения; библиотека гайдов (roundtrip, path traversal); флаги в markdown; структура отчёта |
| `tests/test_server.py` | все REST-ручки детерминированных сценариев: снапшот, статика, девайсы без 500, 409-ошибки вне сессии, CRUD библиотеки, монитор с несуществующими устройствами, WS-снапшот. Работает без Ollama и аудио — то, что гоняет CI |
| `tests/test_e2e.py` | хореография потоков: RingBuffer → чанкер → фейковый ASR → транскрипт (реальные threads, синтетический звук), параметризовано на **обоих** путях нарезки — потоковом и батчевом; полный цикл движка на фейковой LLM: анализ → пропуск пустой дельты → финальная сверка → findings → все файлы сессии + отчёт |

Чего автотесты **не** покрывают (сознательно): реальные бэкенды ASR
(Parakeet, Whisper), реальный Silero (в тестах — энергетический источник
событий, чтобы CI не тянул onnxruntime), реальную Ollama, PortAudio-захват,
pywebview, качество распознавания и качество суждений LLM. Это разделы 2–3.

Правила для новых фич: чистая логика — юнит-тест рядом с существующими;
новая ручка API — сценарий в `test_server.py` (детерминированный, без внешних
зависимостей); изменение поведения движка — тест на слияние/режим.

## 2. Проверка LLM-контура (нужен Ollama, аудио не нужно)

```bash
python -m tools.simulate --guide examples/guide.txt --transcript examples/interview.txt --final
```

Эталонный прогон на приложенных примерах (Qwen3-8B). Критерии прохождения:

- [ ] гайд распарсился в 4 секции, ~12 тем, формулировки не выдуманы;
- [ ] после всех циклов: темы «инструменты», «вчерашний день», «потери задач»,
      «что раздражает», «попытки перехода» — `covered`/`partial`;
      «автоматизация» — `not_covered` (в транскрипте её нет);
- [ ] для непокрытых тем есть готовые вопросы на русском, произносимые вслух;
- [ ] хотя бы одна проба 🔍 по ходу прогона выглядит осмысленной (стикеры,
      «чёрная дыра» заметок — хорошие триггеры);
- [ ] `--final` выдаёт findings с конкретикой (инструменты, случай с аналитикой
      онбординга), не общие слова;
- [ ] ни одного невалидного JSON в логе (`retried` встречается редко, 0–1 раз).

Этот же прогон — регрессионный тест при смене модели (`llm.model`) или правке
промптов: сравнить выдачу до/после.

## 3. Ручной план (перед релизом — на обеих платформах)

Матрица: **Win** = Windows 11, RTX 4070 Super, VB-Cable; **Mac** = macOS 14+,
базовый M4 32 GB, BlackHole 2ch. Отмечать: ✅ / ❌ + комментарий.

### 3.2. Аудио и маршрутизация (самый важный блок)

| # | Шаги | Ожидается |
|---|---|---|
| A1 | Открыть «Настройку», выбрать микрофон | VU-полоска микрофона дёргается от голоса ещё **до** старта сессии |
| A2 | Настроить Zoom→кабель по README, включить тестовый звук в Zoom | VU системного канала дёргается; в наушниках звук слышен (Multi-Output / «Прослушивать») |

| A4 | Тестовый звонок (echo.zoom.us или второй участник), Старт, поговорить с обеих сторон | во вкладке «Транскрипт» появляются и «И», и «Р», с разумными таймстампами; задержка появления реплики ≤ ~5 c (см. R2) |
| A8 | Сказать одну фразу и замолчать; засечь по секундомеру | реплика появляется через 1–3 c, целиком, без срезанного первого слога |
| A9 | Говорить монологом 1–2 минуты без пауз | транскрипт пополняется кусками по `max_chunk_s`, а не молчит до конца; на стыках нет ни задвоенных слов, ни пропавших |

| A5 | Говорить одновременно с респондентом | оба канала записаны, реплики не перемешаны внутри строк |
| A6 | Во время сессии выключить наушники/устройство системного канала | ≤ 15 c: предупреждение «канал не получает звук», VU с красной рамкой; после включения — «канал восстановлен», транскрипция продолжается |
| A7 | Кабель молчит (забыли переключить динамик Zoom) | видно немедленно: VU системного канала мёртв ещё до старта |

## 4. Критерии приёмки релиза

Обязательный минимум перед тегом версии:

1. `pytest` зелёный на обеих платформах (CI — три ОС).
2. Эталонный прогон `simulate` (раздел 2) проходит по всем пунктам.
3. Ручные блоки 3.2 (аудио), 3.4 (сессия), 3.6 (отказоустойчивость) — без ❌
   на **обеих** платформах; остальные блоки — хотя бы на одной.
4. R1–R3 в порогах; R7 (запасной путь на Whisper) не сломан.
5. README-путь установки воспроизведён «с нуля» хотя бы на одной машине.

Быстрый регрессионный набор после мелких правок: `pytest` + simulate +
A4 (звонок со звуком с обеих сторон) + S11/P3 (стоп и отчёт).
