# Форматы данных на диске

Всё, что приложение пишет, лежит открытым текстом в человекочитаемых форматах:
JSON, JSONL, Markdown, WAV. Никакой базы данных нет — папку сессии можно
заархивировать, отдать коллеге или разобрать своим скриптом.

Реализация: [`app/storage/`](../app/storage/).

## Раскладка

```
projects/
  <slug>/
    project.json                       пресет серии
    sessions/
      2026-08-14_18-05-15/             папка сессии
sessions/
  2026-08-16_00-45-17/                 интервью вне проекта — та же структура
guides/
  20260816-005102-тест.json            библиотека гайдов
config.json                            конфиг (пишет человек)
prompts.json                           правки промптов (пишет приложение)
.window.json                           геометрия окна (состояние, не конфиг)
logs/app.log                           ротация 2 МБ × 3, транскрипта не содержит
```

Slug проекта выводится из названия; коллизии разводятся суффиксом `-2`.
Идентификатор сессии — `YYYY-MM-DD_HH-MM-SS` локального времени старта.

Идентификаторы проектов и сессий приходят по HTTP и **проверяются на path
traversal** во всех маршрутах.

## Гарантии записи

Три разных режима, по цене и назначению:

| Режим | Файлы | Как |
|---|---|---|
| **Append + fsync** | `transcript.jsonl`, `flags.jsonl` | Дописывается сразу после события и синхронизируется на диск. Переживает и падение процесса, и **отключение питания** |
| **Атомарная перезапись** | `meta.json`, `guide.json`, `coverage_state.json`, `project.json`, `prompts.json` | tmp → fsync → rename. Файл либо старый целиком, либо новый целиком |
| **Перегенерация** | `transcript.md`, `questions.jsonl` | Переписывается целиком каждый цикл (галочку «задал» снимают и ставят обратно) |

Одного `flush()` мало: он отдаёт байты кэшу ОС, и при пропаже питания теряется
всё, что кэш не успел записать. Цена `fsync` замерена — 36 мс, ~2 % времени
writer-потока.

Битая последняя строка JSONL при чтении **пропускается**: оборванная запись не
должна прятать остальные заметки.

## Папка сессии

### meta.json

Параметры сессии. Атомарная перезапись.

```json
{
  "session_id": "2026-08-14_18-05-15",
  "started_at": "2026-08-14T18:05:15.795822+04:00",
  "stopped_at": "2026-08-14T18:55:02.440867+04:00",
  "analysis_interval_s": 240,
  "llm_model": "qwen3:8b",
  "asr_model": "large-v3-turbo",
  "guide_title": "Интервью с автором Telegram-канала",
  "duration_min": 45,
  "asr_vocabulary": "",
  "project_id": "рассылки",
  "project_title": "Рассылки",
  "segments": 456,
  "xruns_interviewer": 1,
  "xruns_respondent": 0
}
```

| Поле | Смысл |
|---|---|
| `started_at` / `stopped_at` | Wall-clock с таймзоной. **Отсутствие `stopped_at` = сессия оборвана** |
| `segments` | Сколько сегментов распознано |
| `xruns_*` | Переполнения буфера по каналам — индикатор перегруженной машины |
| `audio_seconds` | Длина записи (дописывается при восстановлении) |
| `audio_silence_padded_s` | Сколько тишины добито в молчащий канал (см. [audio.wav](#audiowav)) |
| `audio_warnings` | Сбои записи звука |
| `crashed`, `recovered_at` | Проставляются восстановлением |

### transcript.jsonl

Сегменты распознавания, по одному на строку. Append + fsync после каждого.

```json
{"id": 1, "speaker": "INTERVIEWER", "t0": 8.47, "t1": 10.12, "text": "Алло, добрый день.", "language": null, "created_at": "2026-08-14T18:05:28.853749+04:00"}
```

| Поле | Смысл |
|---|---|
| `id` | Сквозной номер сегмента |
| `speaker` | `INTERVIEWER` (микрофон) или `RESPONDENT` (системный звук) |
| `t0` / `t1` | **Секунды от старта захвата**, не wall-clock. Это позиция в 16 kHz-потоке |
| `text` | Распознанный текст |
| `language` | Язык сессии, если он был назван; `null` — не выбирали |
| `created_at` | Wall-clock момента записи строки |

> **Порядок строк не гарантирован по `t0`.** Два канала пишутся одним ASR-воркером
> в порядке готовности; хронология восстанавливается сортировкой по `t0` при
> чтении.

### transcript.md

Читаемый транскрипт. Перегенерируется каждый цикл из `transcript.jsonl`. Флаги
вшиты хронологически, доп. вопросы — списком в конце.

### audio.wav

Стерео PCM16, 16 kHz: **левый канал — интервьюер, правый — респондент**.
≈230 МБ на час. Отключается `storage.save_audio: false` — транскрипт и отчёт от
записи не зависят.

Две особенности, о которых стоит знать:

- **Заголовок переписывается каждые 2 с** и сбрасывается `fsync`'ом, поэтому файл
  читается плеером даже посреди сессии.
- **Каналы — разные устройства с независимыми часами.** Писатель берёт за раз
  столько кадров, сколько отдали оба; если устройство молчит дольше `STALL_S`,
  его место занимает тишина — иначе выпадение одного микрофона сдвинуло бы всю
  дорожку. Добитая тишина уходит в `meta.audio_silence_padded_s`: **на столько же
  секунд дорожка канала расходится с его `t0`/`t1` в транскрипте**, потому что
  чанкер пропуска устройства не видит.

### guide.json

Разобранная структура гайда. Идентификаторы назначает приложение
детерминированно (`s<N>.t<M>`), не модель.

```json
{
  "guide_id": "g-20260814-164716",
  "language": "ru",
  "title": "Интервью с автором Telegram-канала",
  "sections": [
    {
      "id": "s1",
      "title": "Знакомство",
      "topics": [
        { "id": "s1.t1", "question": "Знакомство", "notes": "…", "priority": "high" }
      ]
    }
  ]
}
```

Рядом лежит **`guide_source.txt`** — гайд ровно тем текстом, который вставил
исследователь. Именно его показывает экран интервью: в `guide.json` формулировки
уже не дословны.

### coverage_state.json

Финальное состояние покрытия. Атомарная перезапись.

```json
{
  "session_id": "2026-08-14_18-05-15",
  "analysis_iteration": 16,
  "updated_at": "2026-08-14T18:54:57.370218+04:00",
  "topics": {
    "s1.t1": {
      "status": "covered",
      "confidence": null,
      "evidence": "Знакомство и представление интервьюера…",
      "last_update_iteration": 1,
      "manual": false
    }
  }
}
```

| Поле | Смысл |
|---|---|
| `status` | `not_covered` < `partial` < `covered` |
| `evidence` | Чем модель обосновала статус |
| `manual` | `true` — метка поставлена человеком, LLM тему больше не трогает |
| `last_update_iteration` | На каком цикле статус последний раз менялся |

**Статус только повышается** — понижения от LLM игнорируются как защита от
мигания между итерациями. Человек этим ограничением не связан.

### recommendations.jsonl

История подсказок по циклам, одна строка на цикл.

```json
{
  "iteration": 1,
  "ts": "2026-08-14T18:09:49.455222+04:00",
  "recommendations": [
    {
      "type": "coverage_gap",
      "topic_id": "s3.t4",
      "urgency": "normal",
      "note": "Не раскрыто, что именно подписчику нужно делать в первые дни.",
      "suggested_question": "Какие первые шаги рекомендуете новым подписчикам?",
      "quote": null,
      "topic_question": "Есть ли что-то, что новый подписчик должен понять…",
      "section_title": "Работа с аудиторией"
    }
  ]
}
```

Типы: `coverage_gap` — непокрытая тема, `probe` — уточнение по свежей реплике
(живёт ровно один цикл и заменяется целиком). Тип — открытая категория:
неизвестные значения проходят движок насквозь и рисуются обобщённым видом.

> ⚠️ Здесь лежат **дословные цитаты респондента** (`quote`). Это самый
> чувствительный файл сессии после аудио.

### flags.jsonl

Отмеченные моменты. Append + fsync.

```json
{"t": 2214.1, "note": "вернуть отписавшегося => или узнать почему", "anchor": "Вы ведёте канал один?", "anchor_section": "Канал и роль Telegram", "topic_id": "s2.t5", "ts": "2026-08-14T18:42:10.146475+04:00"}
```

| Поле | Смысл |
|---|---|
| `t` | Секунды от старта сессии |
| `note` | Текст комментария; пустой — просто закладка (F5) |
| `anchor` / `anchor_section` | Вопрос гайда и раздел, выбранные в момент набора |
| `topic_id` | Тема, к которой относится комментарий |

`anchor` не украшение: без него через неделю не понять, к чему относилась заметка.

### questions.jsonl

Список «спросить дополнительно». Переписывается целиком.

```json
{"id": 1, "t": 899.1, "text": "Кто отвечает подписчикам, когда они пишут?", "done": false, "ts": "2026-08-14T18:20:15.160534+04:00"}
```

### analysis_log.jsonl

Сырые обмены с LLM — для отладки и разбора «почему модель так решила».

```json
{"iteration": 1, "ts": "…", "mode": "delta", "manual": false, "segments": 34,
 "duration_s": 12.4, "prompt_chars": 8210, "eval_count": 412,
 "prompt_eval_count": 3105, "retried": false, "raw_response": "…"}
```

`mode` — `delta` / `reconcile` / `final`. `raw_response` обрезается до 20 КБ.
`retried` — понадобился ли повторный запрос из-за невалидного JSON.

### report.md

Отчёт после «Стоп». Резюме — один небольшой вызов LLM; всё остальное собирается
детерминированно из состояния покрытия и findings, поэтому отчёт валиден даже
если резюме не получилось.

Разделы: резюме · темы со статусами и тезисами · что не раскрыто · отмеченные
моменты · «спросить дополнительно».

## project.json

Пресет серии. Обновляется на старте сессии тем, с чем реально вошли в интервью —
отдельной кнопки «сохранить» нет. Сбой записи пресета сессию не роняет.

```json
{
  "project_id": "рассылки",
  "title": "Рассылки",
  "created_at": "…",
  "updated_at": "…",
  "guide": { },
  "guide_text": "…",
  "asr_vocabulary": "",
  "asr_language": "ru",
  "duration_min": 45,
  "llm_instructions": ""
}
```

`llm_instructions` дописываются к промптам анализа **после** шаблона отдельным
блоком, а не подставляются внутрь: так они переживают любую правку самого
шаблона.

## Библиотека гайдов

`guides/<timestamp>-<slug>.json`:

```json
{ "saved_at": "…", "source_text": "…", "guide": { } }
```

`source_text` хранится, чтобы гайд можно было править и перепарсивать. Имена
файлов проверяются на path traversal.

## prompts.json

Только те промпты, которые исследователь переписал руками. Совпавший с дефолтом
текст **не хранится**, пустой файл удаляется — так правка дефолта в новой версии
доезжает до тех, кто его не трогал.

Ключи: `system_live`, `probes_rule`, `system_final`, `guide_parse`.

Битый файл или испорченный шаблон логируются и заменяются дефолтом: анализ не
должен падать посреди интервью.

## .window.json

Запомненная геометрия окна. Это состояние, а не конфиг — руками не редактируется,
при потере пересоздаётся из дефолтов `window`.

## Восстановление после падения

Незакрытой считается папка, где в `meta.json` **нет `stopped_at`** и нет отметки
`recovered_at` от прошлой починки. [`storage/recovery.py`](../app/storage/recovery.py)
проходит по всем таким папкам один раз при старте сервера — и общим, и внутри
проектов.

Что чинится:

1. **Заголовок `audio.wav`** приводится к фактическому размеру файла: хвост после
   последней синхронизации перестаёт быть невидимым для плееров. Обратный случай
   — данные не доехали до диска — обрезает заголовок до реального размера, чтобы
   файл не читался за EOF.
2. **`transcript.md`** пересобирается из `transcript.jsonl` (оборванная последняя
   строка пропускается) той же функцией, что и по ходу сессии.
3. **В `meta.json`** дописываются `segments`, `audio_seconds`, `crashed: true` и
   `recovered_at`.

Операция идемпотентна. **`report.md` не восстанавливается** — он требует LLM.
Итог уходит в интерфейс первым снимком состояния (`recovered` в `/api/state`).
