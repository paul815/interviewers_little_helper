# API-справочник

Локальный HTTP-сервер (FastAPI) на `http://127.0.0.1:8756`. Он же отдаёт
статику интерфейса. Никакой аутентификации нет — периметр держится на привязке к
loopback и проверке заголовков (см. [«Безопасность»](#безопасность)).

Реализация: [`app/server/app.py`](../app/server/app.py) — маршруты,
[`app/server/controller.py`](../app/server/controller.py) — оркестрация,
[`app/server/hub.py`](../app/server/hub.py) — WebSocket.

## Соглашения

Все тела запросов и ответов — JSON.

| Код | Когда |
|---|---|
| `200` | Успех |
| `400` | Невалидная правка промпта (`PromptError`) — в `detail` объяснение, чего не хватает |
| `409` | Ошибка уровня приложения (`ControllerError`, `ProjectError`) |
| `404` | Нет такого проекта / сессии / файла |
| `422` | Не прошла валидация pydantic |

Ошибки приложения возвращают `{"detail": "человекочитаемый текст"}` — интерфейс
показывает этот текст как есть, поэтому он написан для человека, а не для лога.

## Безопасность

Мидлварь [`OriginGuardMiddleware`](../app/server/security.py) стоит **впереди
маршрутизации**, поэтому покрывает и REST, и `/ws`:

- заголовок `Host` должен быть из `security.allowed_hosts` — защита от DNS
  rebinding, при котором чужой домен резолвится в `127.0.0.1`;
- заголовок `Origin`, если он есть, должен соответствовать разрешённым хостам.
  Это единственная защита `/ws`: WebSocket не подчиняется CORS, и без проверки
  любая открытая во время интервью вкладка читала бы живой транскрипт;
- запросы **без** `Origin` (curl, скрипты) по умолчанию пропускаются —
  `security.require_origin: true` это меняет.

## Статика и состояние

| Метод и путь | Что делает |
|---|---|
| `GET /` | `index.html` |
| `GET /app.css`, `GET /app.js` | Статика интерфейса (без сборки и CDN) |

### `GET /api/state`

Полный снимок состояния — для первой загрузки интерфейса и переподключения.
Тот же объект приходит событием `snapshot` при подключении к `/ws`.

Содержит: состояние сессии, транскрипт, покрытие, рекомендации, флаги, вопросы,
статус ASR/LLM, список проектов, результат восстановления упавших сессий
(`recovered`).

## Устройства и LLM

### `GET /api/devices`

Входные аудиоустройства. При сбое опроса возвращает `{"devices": [], "error": "…"}`
и код `200` — падение подсистемы звука не должно ронять экран настроек.

### `GET /api/llm/status`

```json
{ "ok": true, "server_up": true, "model_found": true, "version": "…", "error": null }
```

### `GET /api/asr/languages`

Языки интервью для вопроса на «Старте»: `{code, model, summary, download_mb, ready}`
по каждому. `ready` — скачаны ли уже веса нужной модели.

## Установка моделей

### `GET /api/setup/status`

Чего не хватает: веса ASR, модель LLM.

### `POST /api/setup/download`

```json
{ "items": ["asr", "llm"], "language": "ru" }
```

Оба поля необязательны: без `items` качается всё недостающее, `language`
указывает, веса какого языка нужны. Прогресс идёт событиями по WebSocket.

## Гайды

### `POST /api/guide/parse`

```json
{ "text": "…свободный текст гайда…" }
```

→ структура гайда (разделы и темы). Один вызов LLM. Идентификаторы тем
назначаются детерминированно на нашей стороне, модель их не выдумывает.

### `GET /api/guides` · `POST /api/guides`

Библиотека. `POST` принимает `{ "guide": {...}, "source_text": "…" }` —
исходный текст хранится, чтобы гайд можно было править и перепарсивать.

### `GET /api/guides/{file_id}` · `DELETE /api/guides/{file_id}`

Загрузить / удалить. Имя файла проверяется на path traversal.

## Промпты

### `GET /api/prompts`

По каждому из четырёх промптов: `{key, title, hint, default, text, customized, placeholders}`.

Ключи: `system_live`, `probes_rule`, `system_final`, `guide_parse`.

### `PUT /api/prompts/{key}`

```json
{ "text": "…" }
```

Неверные подстановки → `400` с объяснением. Проверка при сохранении не
формальность: незнакомая фигурная скобка уронила бы анализ посреди интервью.

### `DELETE /api/prompts/{key}`

Вернуть дефолт. Совпавший с дефолтом текст не хранится — так правка дефолта в
новой версии доезжает до тех, кто его не трогал.

## Проекты

### `GET /api/projects` · `POST /api/projects`

```json
{
  "title": "Онбординг B2B, весна",
  "guide": {},
  "guide_text": "",
  "asr_vocabulary": "",
  "asr_language": "",
  "duration_min": 60,
  "llm_instructions": ""
}
```

Обязателен только `title`. Slug выводится из названия, коллизии разводятся
суффиксом `-2`.

### `GET /api/projects/{id}` · `PATCH /api/projects/{id}`

Пресет проекта. В `PATCH` **`null` значит «не трогать поле»**, а не «очистить» —
поля, которых нет в теле, остаются как были.

### `DELETE /api/projects/{id}`

Только пустой проект. С записанными интервью — `409`: папку с материалами
приложение не удаляет, это делается руками.

### `GET /api/projects/{id}/coverage`

Сводное покрытие серии: по каждой теме — сколько сессий дали `covered` / `partial`
/ `not_covered`. Тема, которую не поднял никто, — повод поправить гайд.

### `POST /api/projects/{id}/open`

```json
{ "session_id": null }
```

Открывает папку в проводнике / Finder. Без `session_id` — папку самого проекта.

## Прошлые интервью

### `GET /api/projects/{id}/sessions`

Список: дата, длительность, покрытие, `has_audio`, `has_transcript`. Новые первыми.

### `GET /api/projects/{id}/sessions/{sid}`

Заметки интервью: флаги, «спросить дополнительно», покрытие.

### `GET /api/projects/{id}/sessions/{sid}/transcript`

Реплики из `transcript.jsonl` вместе с флагами — одной лентой, для просмотра
прошлого интервью.

### `GET /api/projects/{id}/sessions/{sid}/audio`

`audio.wav`. Отдаётся через `FileResponse`, который поддерживает Range-запросы:
без `206` плеер не перематывает.

> Идентификаторы проекта и сессии приходят по HTTP и **проверяются на path
> traversal** во всех маршрутах этой группы.

## Сессия

### `POST /api/session/start`

```json
{
  "mic_index": 1,
  "system_index": 4,
  "guide": {},
  "duration_min": 60,
  "asr_vocabulary": "",
  "asr_language": "ru",
  "project_id": "onbording-b2b",
  "guide_text": "…"
}
```

Обязательны `mic_index`, `system_index`, `guide`.

- `asr_language` — ISO 639-1; пустая строка оставляет выбор модели за
  `config.json` (см. [роутер](CONFIGURATION.md#как-выбирается-модель));
- `guide_text` — оригинальный текст гайда: именно он показывается на экране
  интервью;
- `project_id` — без него сессия уходит в общий `sessions/`.

При старте обновляется пресет проекта: тем, с чем реально вошли в интервью.
Сбой записи пресета сессию не роняет.

### `POST /api/session/stop`

Остановка по порядку: хвост ASR → финальная сверка → отчёт → финальная запись.
Может занять пару минут.

### `POST /api/session/analyze`

Запустить цикл анализа немедленно, не дожидаясь таймера.

## Во время интервью

### `POST /api/session/flag`

```json
{ "note": "", "anchor": "", "anchor_section": "", "topic_id": null }
```

Флаг без текста — просто закладка; с текстом — комментарий. `anchor` /
`anchor_section` несут вопрос гайда, выбранный в момент набора: без него через
неделю не понять, к чему относилась заметка.

### `POST /api/session/question` · `POST /api/session/question/done`

```json
{ "text": "спросить про интеграцию с CRM" }
```
```json
{ "question_id": 3, "done": true }
```

Список «спросить дополнительно». Галочку снимают и ставят обратно, поэтому
`questions.jsonl` переписывается целиком.

### `POST /api/topics/status`

```json
{ "topic_id": "s2.t3", "status": "covered" }
```

`status` — `covered` / `partial` / `not_covered` / `null`. Ручная метка сильнее
LLM: тема с меткой перестаёт обновляться автоматикой. `null` снимает метку.
Исследователь может ставить любой статус, в том числе **ниже** текущего — на
автоматику это ограничение не распространяется, а на человека распространяться
не должно.

### `POST /api/recommendations/dismiss`

```json
{ "topic_id": "s2.t3" }
```

Скрыть подсказку по теме — до ручного изменения статуса.

## WebSocket `/ws`

Конверт: `{"type": ..., "payload": {...}}`. При подключении сразу приходит
`snapshot`, дальше — события по мере наступления.

| type | payload (главное) | Источник |
|---|---|---|
| `snapshot` | То же, что `GET /api/state` | При подключении |
| `segment` | Сегмент транскрипта | ASR-воркер (threadsafe-мост) |
| `coverage` | `{topics, counts, iteration}` | После анализа или ручной метки |
| `recommendations` | `{items, probes, iteration}` | После live-анализа или dismiss |
| `analysis` | `{phase: started\|done\|failed, mode, …}` | Движок покрытия |
| `timer` | `{next_analysis_at, interval_s}` | Планировщик; отсчёт клиент ведёт сам |
| `status` | `{state?, message, asr?}` | Контроллер / движок |
| `error` | `{message}` | Любой сбой, требующий внимания |
| `session` | `{state, session_id, started_at, duration_min, project_id, project_title}` | Старт / стоп |
| `levels` | `{monitor, interviewer?, respondent?}`, ~8 Гц | Монитор / watchdog |
| `channel` | `{speaker, alive, device}` | Watchdog при смене живости канала |
| `flag` | `{t, note, anchor, anchor_section, topic_id, ts}` | Флаг или комментарий |
| `question` | `{id, t, text, done, ts}` | Доп. вопрос или галочка на нём |

**Почему у карточки подсказки есть «раздел → вопрос».** Анализ приходит с
задержкой в цикл, когда разговор уже ушёл вперёд. Поэтому каждая карточка
подписана местом в гайде, пришедшие в последнем цикле подсвечены, а клик по
карточке ведёт гайд к нужному блоку. Темы блока хранятся списком (`topicIds`):
разбор дробит один абзац гайда на несколько тем.

## Пример: снять состояние из консоли

```bash
curl -s http://127.0.0.1:8756/api/state | python -m json.tool
```

Работает, потому что `security.require_origin` по умолчанию `false`. Для
небраузерных клиентов при `true` нужно слать `Origin: http://127.0.0.1:8756`.
