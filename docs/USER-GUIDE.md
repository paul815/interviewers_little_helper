## 1. Требования

| | macOS | Windows | Linux |
|---|---|---|---|
| Железо | Apple Silicon (M4+), 32 GB | NVIDIA RTX 4070 Super (12 GB VRAM), 32 GB RAM | 32 GB RAM |
| ОС | macOS 14+ | Windows 10 22H2+ / Windows 11 | — |
| Python | 3.11+ | 3.11+ | 3.11+ |
| Захват системного звука | [BlackHole 2ch](https://existential.audio/blackhole/) | WASAPI loopback — ставить нечего | PulseAudio/PipeWire, настраивается средствами системы |
| LLM-сервер | [Ollama](https://ollama.com) | [Ollama](https://ollama.com) | [Ollama](https://ollama.com) |

> **Про Linux.** Приложение на нём запускается, `setup.py` его понимает, и тесты
> гоняются в CI на Ubuntu. Но виртуальный кабель там делается средствами системы
> (PulseAudio/PipeWire), приложение его не детектит и не ставит, а ручные
> чек-листы приёмки прогоняются только на Windows и macOS. Считайте Linux
> рабочим, но не проторённым путём.

**Наушники обязательны.** Если звук респондента идёт из колонок, микрофон
подхватит его, и реплики продублируются в канале интервьюера. Эхоподавления в
приложении нет.

Видеокарта нужна только для LLM. Parakeet по умолчанию работает на CPU и
видеопамять не занимает вообще — вся она достаётся Ollama.

## 2. Установка

### 2.0. Самый короткий путь — ярлык (Windows)

Двойной клик по **`Launch ILH.lnk`** в корне репозитория. Ярлык — единственное,
что нужно нажимать в обычной жизни: при первом запуске он сам вызовет `setup.py`
(окружение, зависимости, веса ASR, Ollama), а дальше просто поднимает приложение.

Как это устроено: ярлык указывает на `tools/launch_win.bat`, тот передаёт работу
своей же скрытой копии — она и владеет процессом приложения, — а видимое окно
показывает стадии запуска и закрывается само, как только приложение ответило на
своём порту. Если приложение не поднялось за 120 с, окно останется открытым с
путями к логам и хвостом `logs/launcher-runner.log`.

Приложение уже запущено — ярлык не поднимает второй экземпляр: он говорит об этом
и открывает вкладку браузера на тот же адрес (окно легко теряется за Zoom).

Посмотреть падение живьём, не в логах:

```powershell
set ILH_DIAGNOSTIC_LAUNCH=1 && tools\launch_win.bat
```

Ярлык хранит и относительный путь, поэтому переживает перенос папки. Если он всё
же потерялся — пересоздать (`-Desktop` положит копию ещё и на рабочий стол):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make_shortcut.ps1
```

На macOS/Linux ярлыков нет — тот же сценарий даёт `tools/launch_mac.command`
(двойной клик в Finder; при первом запуске так же вызывает `setup.py`). Если
репозиторий приехал с Windows, бит запуска придётся вернуть один раз руками:

```bash
chmod +x tools/launch_mac.command tools/reset_mac.command
```

Всё, что ниже, — ручной путь и подробности того, что делает ярлык.

### 2.1. Python-окружение

Скрипт установки один на все платформы:

```bash
python3 setup.py    # macOS / Linux
```
```powershell
python setup.py     # Windows
```

Он создаёт `.venv`, ставит зависимости под вашу ОС, качает веса ASR, а затем
предлагает доставить внешние компоненты — про каждый спрашивает отдельно:

| Компонент | macOS | Windows |
|---|---|---|
| Ollama | `brew install --cask ollama` | `winget install Ollama.Ollama` |
| Модель LLM | `ollama pull` (имя берётся из `config.json`) | то же |
| Системный звук | `brew install blackhole-2ch` | не требуется — WASAPI loopback |

Сервер Ollama скрипт поднимает сам, так что после установки шаг 2.2 можно
пропустить. На Windows шаг 3 тоже не нужен: системный звук берётся прямо с
устройства вывода.

Единственное, что скрипт не ставит молча, — **VB-Cable на Windows**: это драйвер,
ему нужны права администратора и перезагрузка, а тихой установки вендор не даёт.
Но он и не нужен в обычном случае (см. §3).

**Флаги `setup.py`:**

| Флаг | Что делает |
|---|---|
| `-y` / `--yes` | Ставить всё без вопросов |
| `--no-extras` | Только Python-окружение; не трогать Ollama и кабель |
| `--recreate` | Пересоздать `.venv` с нуля |
| `--skip-model` | Не качать веса ASR |
| `--requirements <файл>` | Свой набор зависимостей |

Скрипт идемпотентен: повторный запуск ничего не ломает и работает как проверка
окружения.

Если что-то не доехало, доскачать можно и из самого приложения: при запуске оно
показывает мастер с прогрессом (**⚙ Настройки приложения** → строка «Модели» → ⤓).

**Вручную то же самое:**

```bash
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements-macos.txt    # или -windows.txt / -common.txt (Linux)
python -m tools.fetch_asr_model
```

На Windows свежий драйвер NVIDIA нужен, только если вы переключитесь на Whisper
(`asr.backend: faster`) — Parakeet по умолчанию работает на CPU. CUDA Toolkit
ставить не нужно: cuBLAS/cuDNN приезжают pip-пакетами, приложение само подключает
их DLL. Если CUDA недоступна, Whisper откатится на CPU.

### 2.2. Ollama и модель

Если `setup.py` уже поставил Ollama и модель — этот шаг пропускайте. Вручную:

1. Установите Ollama с [ollama.com](https://ollama.com) и запустите её.
2. Скачайте модель:
   ```bash
   ollama pull qwen3:8b
   ```

Опциональный тюнинг (экономия VRAM, особенно на Windows) — переменные окружения
для Ollama: `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0`.

Модель может быть любой из Ollama; имя должно совпадать с `llm.model` в конфиге.
На M4 Pro/Max комфортно идёт `qwen3:14b`.

## 3. Виртуальное аудиоустройство

Разделение говорящих делается **на уровне ОС**, а не диаризацией: микрофон =
интервьюер, системный звук (выход Zoom) = респондент. Поэтому канал респондента
нужно откуда-то взять.

### Windows — ничего ставить не нужно

Системный звук берётся прямо с устройства вывода через WASAPI loopback
(см. [app/audio/loopback.py](../app/audio/loopback.py)). В приложении выберите в
поле «Системный звук» свои наушники — те же, в которые играет Zoom. Ни VB-Cable,
ни настройка Zoom, ни «Прослушивать с данного устройства» не нужны.

Пункт «(WASAPI loopback)» в списке устройств — это и есть нужный вход; приложение
подставляет текущее устройство вывода само.

### macOS — BlackHole + Multi-Output Device

На macOS аналога loopback без нативного кода нет, поэтому виртуальное устройство
пока нужно:

1. Установите BlackHole 2ch: `brew install blackhole-2ch` (или инсталлятором с
   сайта), перезагрузитесь при необходимости.
2. Откройте **Audio MIDI Setup** (Настройка Audio-MIDI).
3. Кнопкой «+» внизу слева создайте **Multi-Output Device** и отметьте в нём:
   - ваши наушники/динамики (галочка первой строкой),
   - **BlackHole 2ch**.
4. В **Zoom → Settings → Audio → Speaker** выберите созданный **Multi-Output
   Device**. Теперь вы слышите респондента в наушниках, и та же дорожка идёт в
   BlackHole.
5. В приложении: «Системный звук» = **BlackHole 2ch**, «Микрофон» = ваш микрофон
   (тот же, что выбран в Zoom как Microphone).

### Windows — VB-Cable (запасной путь)

Нужен, только если loopback почему-то недоступен (например, не встал
`PyAudioWPatch`).

1. Установите VB-Cable (распаковать, правой кнопкой на `VBCABLE_Setup_x64.exe` →
   запустить от администратора), перезагрузитесь.
2. В **Zoom → Settings → Audio → Speaker** выберите **CABLE Input (VB-Audio
   Virtual Cable)**.
3. Чтобы слышать респондента: **Параметры звука Windows → Панель управления
   звуком → вкладка «Запись» → CABLE Output → Свойства → вкладка «Прослушать»** →
   включите **«Прослушивать с данного устройства»** и выберите свои наушники.
   (Появляется небольшая задержка монитора — это нормально.)
4. В приложении: «Системный звук» = **CABLE Output (VB-Audio Virtual Cable)**,
   «Микрофон» = ваш микрофон.

## 4. Запуск

```bash
python -m app.main            # окно в правой половине экрана, поверх других окон
python -m app.main --browser  # то же в обычной вкладке браузера
```

По умолчанию окно занимает правую половину экрана во всю высоту: слева созвон,
справа помощник. Оно **тянется за край**, и растянутый размер запоминается —
применится при следующем запуске. Стартовый размер, минимум и «поверх остальных»
настраиваются в блоке `window` конфига (см. [CONFIGURATION.md](CONFIGURATION.md#window)).

Если моделей не хватает, приложение при запуске само предложит их скачать и
покажет прогресс — терминал не нужен. То же окно открывается из **⚙ Настройки
приложения** → строка «Модели» → ⤓.

Из консоли то же самое:

```bash
python -m tools.fetch_asr_model    # Parakeet, ~670 МБ в кэш HuggingFace; дальше офлайн
```

## 5. Порядок работы

### Шаг 0. Список проектов

Приложение открывается **списком проектов**. Карточка показывает число записанных
интервью, дату последнего и длительность; клик открывает проект, «⋯» —
папку, переименование и удаление.

Кнопка **«Записать без проекта»** — для разового интервью, оно уйдёт в общий
`sessions/`.

Строка сверху показывает готовность: микрофон, системный звук, модели, LLM.
**Чинить лучше здесь, а не за минуту до созвона.**

Вернуться к списку из проекта — кнопкой **←** в шапке.

**Настроек две, и делятся они по владельцу:**

| Где | Что там |
|---|---|
| **⚙ «Настройки приложения»** | Общее на машину: тема, LLM, модели, устройства, промпты анализа |
| Вкладка **«Настройки проекта»** | То, что меняется от исследования к исследованию: длительность, гайд, доп. инструкции, словарь терминов |

### Шаг 1. Проверить LLM

Откройте **⚙** и посмотрите на индикатор LLM — должно быть «✓ Ollama…».

### Шаг 2. Выбрать устройства

Там же выберите **микрофон** и **системный звук** (на Windows подставляется
loopback текущего устройства вывода, на macOS — BlackHole).

Под каждым устройством — **полоска уровня**: скажите фразу и включите тестовый
звук в Zoom, обе должны дёргаться. Это главная страховка от «пустого канала».
Полоски живут в этом диалоге: пока он открыт, звук слушается и до старта сессии.

Если у обоих каналов выбрано одно устройство, приложение не даст стартовать.

### Шаг 3. Гайд и параметры

Вкладка **«Настройки проекта»**:

1. **Гайд** — возьмите из **библиотеки** (если уже парсили) или вставьте текст →
   **«Распарсить гайд»** → проверьте структуру → **«Использовать эту структуру»**.
   Гайд сохранится в библиотеку.
2. **Длительность интервью** — от неё считается строка темпа.
3. **Словарь терминов** (по желанию) — названия продукта, бренды, жаргон.
   ⚠️ Работает **только с Whisper** (`asr.backend: faster` или `mlx`). Parakeet,
   стоящий по умолчанию, подсказку промптом не поддерживает и предупредит об
   этом в шапке.
4. **Доп. инструкции для LLM** (по желанию) — см. §9.

### Шаг 4. Старт

Нажмите **Старт**. Приложение спросит **язык интервью** (см. §8), затем в шапке
пойдёт таймер до следующего анализа (по умолчанию 4 минуты). Кнопка **«Анализ»**
запускает цикл немедленно.

### Шаг 5. Во время интервью

Основная вкладка — **Интервью**. Слева гайд ровно тем текстом, который вы
вставили (кнопки A−/A+ меняют кегль), справа две колонки.

**Гайд слева:**
- клик по вопросу делает его текущим;
- комментарий, отправленный по ⏎, сохраняется с отметкой времени и с этим
  вопросом — в `flags.jsonl` и в `transcript.md`.

**Правая колонка сверху — подсказки LLM:**
- строка **темпа**;
- **пробинг-вопросы** (🔍) по свежим репликам респондента;
- **непокрытые темы** с готовыми формулировками: ⧉ копирует вопрос, ✕ скрывает
  подсказку по теме.

Анализ приходит раз в несколько минут, когда разговор уже ушёл вперёд, поэтому
каждая карточка подписана «раздел → вопрос», новые несколько секунд подсвечены,
а клик по карточке возвращает гайд к нужному вопросу.

**Правая колонка снизу — «спросить дополнительно»:** записали по ходу, задали,
поставили галочку; список уезжает в отчёт.

**Яркий момент** без текста — кнопка 🚩 или клавиша **F5**.

**Спорить с LLM можно:** во вкладке **Темы** клик по теме помечает её покрытой
вручную (✔ — LLM больше её не трогает), повторный клик снимает метку. Ручная
метка сильнее любого вывода модели.

Если канал перестал получать звук (отвалились наушники), приложение предупредит
и попробует переоткрыть устройство.

### Шаг 6. Стоп

Приложение дораспознаёт хвост аудио, делает финальную сверку **всего** транскрипта
с гайдом и собирает отчёт. Это может занять пару минут — статус виден в шапке.

### Шаг 7. Вкладка «Проект»

Взгляд на серию целиком:

- **список записанных интервью** — дата, длительность, покрытие, 📂 открывает папку;
- **сводное покрытие** — в скольких интервью тема раскрыта. Тема, которую не
  поднял никто, светится красным: это и есть повод поправить гайд к следующему
  разговору;
- **🎧 открывает расшифровку прошлого интервью вместе с записью**: реплики с
  таймкодами и флаги одной лентой, плеер сверху, клик по строке проматывает
  запись на этот момент и подсвечивает звучащую реплику. Если аудио не
  сохранялось, иконка 📄 — остаётся один текст.

## 6. Проекты

Проект — серия интервью по одному гайду. Он держит пресет и свои сессии:

```
projects/онбординг-b2b-весна/
  project.json                  — гайд, словарь ASR, длительность, доп. инструкции
  sessions/2026-08-08_10-15-00/ — обычная папка сессии (§10)
  sessions/2026-08-08_19-40-11/
```

Свойства, которые стоит знать:

- **Пресет догоняет реальность сам.** С чем вошли в интервью — то проект и
  запомнит; отдельной кнопки «сохранить» нет.
- **Выбранный проект переживает перезапуск.**
- **Удалить через интерфейс можно только пустой проект.** Папку с записанными
  интервью приложение не трогает — это делается руками.
- **Slug выводится из названия**, коллизии разводятся суффиксом `-2`.

Можно вести несколько исследований параллельно и переключаться между ними одним
выпадающим списком — утренняя серия и вечерняя не путаются.

## 7. Гайды и библиотека

Гайд вставляется свободным текстом и разбирается LLM на структуру: разделы →
темы. Идентификаторы тем назначает приложение детерминированно, не модель.

Разобранный гайд попадает в **библиотеку** (`guides/`) вместе с исходным текстом
— поэтому его можно достать, поправить и перепарсить. ✕ рядом с элементом
библиотеки удаляет гайд и сначала спрашивает подтверждение.

В сессии сохраняются оба варианта: `guide_source.txt` — ровно ваш текст (его и
показывает экран интервью), `guide.json` — разбор LLM, где формулировки уже не
дословны.

**Разумный размер гайда — до ~40 тем.** Весь гайд, состояние покрытия и дельта
транскрипта должны помещаться в контекст LLM.

## 8. Язык интервью

При старте сессии приложение спрашивает язык — и от ответа зависит, какая модель
будет распознавать:

| Язык | Модель | Почему |
|---|---|---|
| Русский | **GigaAM v3 E2E** (227 МБ) | Заметно точнее Parakeet на русском, плюс восстанавливает пунктуацию и нормализует числа |
| Один из 25 европейских | **Parakeet TDT v3** (671 МБ) | Быстрый дефолт |
| Всё остальное | **Whisper** | Ни одна наша onnx-модель этот язык не знает |

Последний пункт — тихая, но важная победа. Whisper определяет язык по первым
30 секундам того, что ему дали, а дают ему один VAD-чанк — часто полторы секунды
«ммм». Названный заранее язык убирает подбрасывание монетки, которое при
неудачном исходе выдаёт уверенный текст не в том алфавите.

Язык записывается в транскрипт в любом случае, даже там, где на декодирование он
не влияет (Parakeet и GigaAM языко-агностичны на инференсе) — чтобы через месяц
было понятно, чем это распознавали.

Проект запоминает свой язык. Ключ `asr.language` в конфиге — только то, чем
заполнен вопрос при первом «Старте».

## 9. Что приложение спрашивает у модели

### Доп. инструкции проекта

Во вкладке **«Настройки проекта»** есть поле **доп. инструкций** — контекст
именно этой серии: кто респонденты, на что смотреть особенно внимательно, чего не
предлагать.

> «респонденты — врачи»
> «не предлагай вопросы про цену — их задаёт другая команда»

Инструкции добавляются к промптам анализа всех интервью проекта — **после**
шаблона, отдельным блоком, а не подставляются внутрь. Поэтому они переживают
любую правку самого шаблона.

### Сами промпты

Если этого мало, промпты открыты: **⚙ → Промпты анализа** показывает четыре
текста, которые уходят в модель:

| Ключ | Что это |
|---|---|
| `system_live` | Цикл анализа во время интервью |
| `probes_rule` | Правило пробинг-вопросов |
| `system_final` | Финальная сверка на «Стоп» |
| `guide_parse` | Разбор текста гайда на структуру |

Их можно переписать под своё исследование; у каждого есть «Вернуть дефолт».

**Подстановки в фигурных скобках** (`{guide_block}` — сам гайд, `{probes_rule}` —
правило проб) заполняет приложение, и удалить их нельзя: такую правку оно не
примет и объяснит, чего не хватает. Проверка происходит при сохранении — иначе
незнакомая фигурная скобка уронила бы анализ посреди интервью.

Правки лежат в `prompts.json` рядом с `config.json` и применяются **к следующему
запущенному интервью**: начатая сессия доигрывает по тем промптам, с которыми
стартовала. Совпавший с дефолтом текст не хранится — так правка дефолта в новой
версии доезжает до тех, кто его не трогал.

## 10. Что сохраняется

`projects/<проект>/sessions/2026-07-11_14-30-00/` (или `sessions/…` без проекта):

| Файл | Что это |
|---|---|
| `transcript.jsonl` | Сегменты с говорящим и таймштампами (append по ходу — переживает сбой) |
| `transcript.md` | Читаемый транскрипт |
| `audio.wav` | Запись интервью: стерео 16 kHz, слева интервьюер, справа респондент (≈230 МБ/час; `storage.save_audio: false` отключает) |
| `guide.json` | Подтверждённая структура гайда |
| `guide_source.txt` | Исходный текст гайда, как его вставил исследователь |
| `coverage_state.json` | Финальное состояние покрытия |
| `recommendations.jsonl` | История рекомендаций по циклам |
| `report.md` | Отчёт (см. §11) |
| `flags.jsonl` | Отмеченные моменты и комментарии |
| `questions.jsonl` | «Спросить дополнительно» с галочками |
| `analysis_log.jsonl` | Сырые обмены с LLM (для отладки) |
| `meta.json` | Параметры сессии |

Библиотека гайдов лежит отдельно, в `guides/`. Полное описание форматов с
разбором каждого поля — в [DATA-FORMATS.md](DATA-FORMATS.md).

**Сессия, оборванная падением**, остаётся без `stopped_at` и `report.md`. Папку
дочинивает `storage/recovery.py` при следующем запуске: заголовок WAV приводится
к фактическому размеру файла, `transcript.md` пересобирается из `transcript.jsonl`,
в `meta.json` дописываются `crashed: true` и `recovered_at`. Результат показывается
строкой статуса при старте.

## 11. Отчёт

Собирается после «Стоп» (`analysis.report: true`) и содержит:

- **резюме** — одна небольшая LLM-заявка поверх итогового состояния;
- **темы со статусами** и тезисы (`findings`), собранные финальной сверкой;
- **что не раскрыто**;
- **отмеченные моменты** — флаги и комментарии;
- **«спросить дополнительно»** — списком.

Детерминированная часть собирается из состояния покрытия и findings, поэтому
отчёт остаётся валидным, даже если LLM-резюме не получилось.

## 12. Сброс

Вернуть рабочую копию в состояние «как из репозитория»:

```powershell
tools\reset_win.bat
```
```bash
tools/reset_mac.command
```

Скрипт останавливает приложение и сносит всё в корне, чего нет в исходниках:
`.venv`, `logs/`, `sessions/`, `guides/`, `config.json`, кэши. Перед вопросом он
печатает точный список того, что удалит; продолжает только по ответу `Yes` —
любой другой ввод (и пустой) отменяет.

Гасится при этом только *свой* Python: сначала PID из `logs/launcher.pid` (и то
после сверки, что процесс всё ещё принадлежит этой папке — PID'ы
переиспользуются), затем `python.exe`/`pythonw.exe`, чей командный запуск ведёт
из этого каталога. Чужой Python — Jupyter, другие проекты — не трогается.

**Что переживает сброс:** исходники, история git, а также веса ASR (кэш
HuggingFace) и модели Ollama — они лежат вне репозитория, и качать их заново
незачем.

Флаг `--keep-venv` сохраняет `.venv`: цикл «сбросил — запустил» становится
секундным вместо минутного. Но лончер вызывает `setup.py`, только когда `.venv`
нет, — то есть с этим флагом первый запуск не проверяется. Перед проверкой
релиза запускайте без него.

## 13. Проверка без интервью

**Движок покрытия на текстовом транскрипте** (нужен только Ollama, без аудио):

```bash
python -m tools.simulate --guide examples/guide.txt --transcript examples/interview.txt --final
```

`--final` дополнительно прогоняет финальную сверку и печатает тезисы для отчёта.

**Скорость распознавания на своём железе** — на любой записи:

```bash
python -m tools.bench_asr запись.wav
```

Печатает RTF по каждому доступному бэкенду.

**Тесты:**

```bash
pip install -r requirements-dev.txt
pytest
```

Тот же набор (включая E2E конвейера на фейковых ASR/LLM и API-тесты) гоняется в
GitHub Actions на Linux/macOS/Windows. Ручные чек-листы и критерии приёмки — в
[TESTING.md](TESTING.md).

## 14. Устранение неполадок

| Симптом | Что делать |
|---|---|
| «Ollama не отвечает» | Запустите приложение Ollama / `ollama serve`; проверьте `llm.base_url` |
| «Модель не найдена» | `ollama pull qwen3:8b` (имя должно совпадать с `llm.model`) |
| Долгая пауза при первом старте | Не скачаны веса ASR: `python -m tools.fetch_asr_model` |
| «Словарь терминов проигнорирован» в шапке | Parakeet не умеет подсказку промптом. Нужен словарь — `asr.backend: faster` |
| Транскрипт пустой, хотя полоски уровня дёргаются | Смотрите `logs/app.log`: если там «VAD: энергетический», Silero не загрузился (проверьте `onnxruntime` и `app/audio/data/silero_vad.onnx`) |
| Реплики рвутся на середине фразы | Увеличьте `audio.vad_redemption_s` (например до 1.0) |
| faster-whisper не видит CUDA | Обновите драйвер NVIDIA; проверьте pip-пакеты `nvidia-cublas-cu12`, `nvidia-cudnn-cu12`; смотрите `logs/app.log` — при неудаче ASR сам уйдёт на CPU |
| Не открывается аудиоустройство | Проверьте разрешение на микрофон (macOS: Системные настройки → Конфиденциальность → Микрофон; терминалу/IDE тоже нужно разрешение) |
| В канале респондента тишина | **Windows:** «Системный звук» должен быть тем устройством вывода, в которое реально играет Zoom (ищите пункт с пометкой WASAPI loopback). **macOS:** Zoom должен выводить звук в BlackHole (§3); проверьте, что в Zoom не включён «оригинальный звук» на другое устройство |
| В списке нет пунктов «(WASAPI loopback)» | Windows: не установлен `PyAudioWPatch` — `pip install -r requirements-windows.txt`. Запасной путь — VB-Cable |
| Окно не появляется (Windows) | Установите [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) или запустите с `--browser` |
| Анализ дольше пары минут | Модель не влезла в VRAM и уехала на CPU — пройдите лестницу деградации из [CONFIGURATION.md](CONFIGURATION.md#vram) |
| Реплики дублируются в канале интервьюера | Вы работаете без наушников. Эхоподавления нет |
| Приложение не даёт стартовать | У микрофона и системного звука выбрано одно устройство |

Логи: `logs/app.log` (ротация 2 МБ × 3, текста транскрипта не содержит).
