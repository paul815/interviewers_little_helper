# Пересмотр подхода: удобство работы пользователя

Рабочий документ, не пользовательская документация. Разбор продукта с нуля —
глазами исследователя, который ведёт серию интервью, а не глазами разработчика,
который знает, где что лежит. Ссылки на код — доказательства, а не задачи.

Дата: 2026-08-20. Ветка: `claude/stenoai-approach-review-mebw12`.

---

## 0. Кто пользователь и в чём главный конфликт

**Пользователь:** качественный исследователь / продакт / UX-ресёрчер. Проводит
5–20 интервью на исследование, по 45–90 минут, часто подряд по два-три в день.
Почти наверняка не разработчик. Ноутбук может быть корпоративным (без прав
администратора). Во время интервью его внимание занято живым человеком.

**Главный конфликт продукта:**

> Приложение просит смотреть в экран в тот момент, когда единственная важная
> задача — смотреть на собеседника и слушать.

Всё остальное — производные от этого конфликта. Сейчас на экране интервью три
скроллящиеся колонки, вкладки, таймер, строка темпа, лента транскрипта и лента
подсказок. Это интерфейс аналитика, а не интерфейс человека в разговоре.
Побочный эффект: самая ценная часть продукта (что осталось не раскрыто) требует
чтения именно тогда, когда читать нельзя.

**Второй конфликт, менее заметный:** продукт заканчивается там, где у
исследователя работа только начинается. Интервью останавливается — и результат
уезжает в папку на диске. В приложении отчёта нет вообще
(`app/server/controller.py:512` пишет `report.md` и сообщает об этом строкой
статуса; UI его не показывает). Всё, ради чего записывали, живёт вне продукта.

## 2. Установка и первый запуск

### 2.1. Порог входа отсекает целевого пользователя

**Что не так.** README предлагает `git clone` + `python setup.py`
(README.md:51). Дальше — Ollama, модель на 5 ГБ, веса ASR, 32 ГБ RAM, на macOS
ещё BlackHole и Multi-Output Device. Для исследователя это не установка, а
проект на вечер. `Launch ILH.lnk` есть, но упомянут вторым и только для Windows.

**Почему больно.** Продукт локальный — это его главное преимущество (приватность
интервью). Но локальность оплачивается установкой, и платит за неё тот, кто
меньше всего к этому готов.

**Решения (по возрастанию стоимости):**

1. **Переставить акценты в README и в шорткате.** Первым экраном — «скачайте
   архив, распакуйте, двойной клик». `setup.py` — во второй раздел, «для тех,
   кто работает с кодом». Стоимость: час. Не решает проблему, но перестаёт
   отпугивать на первом абзаце.
2. **GUI-установщик вместо терминала.** `setup.py` при двойном клике открывает
   окно (tkinter достаточно) с четырьмя строками прогресса: окружение →
   зависимости → распознавание → подсказки. Ошибка показывается человеческим
   текстом и кнопкой «открыть лог». Терминальный режим остаётся под флагом.
   Стоимость: 2–3 дня.
3. **Собранная сборка.** PyInstaller/Briefcase → `.exe` + `.dmg` с вшитым
   Python; веса и Ollama докачиваются из приложения (мастер уже есть —
   `renderSetup`, `app/web/app.js:931`). Подпись кода на Windows и нотаризация
   на macOS — иначе SmartScreen/Gatekeeper съедят половину пользователей.
   Стоимость: 1–2 недели + сертификат. **Рекомендую как цель.**

### 2.2. Требования к железу выясняются постфактум

**Что не так.** 32 ГБ RAM и `qwen3:8b` (config.example.json) — жёсткая стена. Ни
установщик, ни приложение не говорят заранее: «на твоей машине это будет
работать вот так».

**Решения:**

1. **Проба железа при первом запуске:** RAM, VRAM, платформа → выбор ступени
   («8B — полный режим», «4B — подсказки реже», «без подсказок — только запись и
   транскрипт»). Показать выбор человеку с одной строкой объяснения и дать
   переключить.
2. **Замер вместо характеристик:** прогнать один короткий цикл анализа на
   тестовом тексте и показать «анализ занимает ~35 c — это нормально» или
   «~4 минуты — подсказки будут опаздывать, включите режим без подсказок».
   Честнее, чем гигабайты. Стоимость: день, уже есть `tools/bench_asr.py`.
3. **Явный режим «только запись»** как полноценный, а не как деградация
   (см. 3.2) — тогда слабое железо перестаёт быть блокером.

### 2.3. Первый запуск не ведёт за руку

**Что не так.** Первый экран — список проектов (пустой) и строка готовности с
пунктами «Guide / Microphone / System audio / Recognition / Hints»
(`app/web/app.js:1136`). Формулировки технические, кнопка «Fix» ведёт в диалог
целиком, а не к сломанному пункту.

**Решения:**

1. **Онбординг-шаги вместо строки чек-листа**: три экрана — «звук» (выбор
   устройств + проверка), «подсказки» (модели), «первое исследование» (гайд).
   Показывается один раз, потом доступен из ⚙.
2. **Оставить строку, но сделать её кликабельной попунктно:** клик по красному
   пункту ведёт ровно туда, где он чинится (сейчас `bad.every(c => c.guide)`
   решает за пользователя). Стоимость: полчаса.
3. **Переименовать пункты на язык задачи:** «Гайд» → «Гайд исследования»,
   «Hints»/«LLM» → «Подсказки», «Recognition» → «Распознавание речи». Слово
   «LLM» в интерфейсе исследователя не нужно нигде.

## 3. Подготовка исследования

### 3.1. Гайд обязателен, и его разбирает LLM

**Что не так.** `canStart()` (`app/web/app.js:267`) требует
`S.guideConfirmed`. Разбор гайда — запрос к LLM (`parseGuide`,
`app/web/app.js:1746`). Значит: **нет Ollama → нет разобранного гайда → нельзя
даже начать запись.** Одна сломанная зависимость блокирует функцию (диктофон),
которая от неё не зависит.

**Решения:**

1. **Разрешить старт без гайда.** Экран интервью в этом режиме: транскрипт,
   комментарии, флаги, «спросить дополнительно». Колонка подсказок говорит
   «гайд не задан — подсказок не будет». Стоимость: полдня. **Обязательно.**
2. **Детерминированный парсер как основной, LLM — как улучшение.** Нумерация,
   отступы, заголовки, пустые строки покрывают 80% реальных гайдов. Результат
   всегда показывается деревом с возможностью править руками (сейчас правка
   возможна только через возврат к тексту и повторный разбор).
3. **Ручное дерево.** Кнопка «собрать гайд вручную»: раздел → вопрос,
   drag-n-drop. Нужна всё равно — LLM ошибается на длинных гайдах, и сейчас
   единственный способ поправить одну формулировку — переразобрать всё.

### 3.2. Нет режима «просто запиши и расшифруй»

**Что не так.** Продукт позиционируется как помощник в интервью, но половина
ценности — транскрипт с таймкодами. Сейчас к нему нельзя прийти коротким путём:
нужны и гайд, и LLM, и модель.

**Решения:**

1. **Кнопка «Записать» на стартовом экране** рядом с «Новый проект»: запись
   начинается за один клик, гайд можно подцепить позже, анализ — задним числом.
2. **Расшифровка готового файла.** Перетащил `.mp3`/`.m4a` из Zoom — получил
   транскрипт и, если есть гайд, покрытие. Это снимает зависимость от аудио-
   маршрутизации целиком и открывает продукт тем, у кого интервью уже записаны.
   Стоимость: 2–3 дня (конвейер ASR уже есть, нужен вход и прогресс).
   **Самая дешёвая большая функция в списке.**
3. **Постанализ существующей сессии:** «проанализировать заново» для завершённого
   интервью — после того, как поправили гайд или промпты.

### 3.3. Вопрос о языке задаётся в самый неудобный момент

**Что не так.** `askLanguage()` (`app/web/app.js:896`) открывает модалку на
каждом «Старт», хотя ответ уже сохранён в проекте. Респондент в этот момент уже
в звонке.

**Решения:**

1. **Спрашивать при создании проекта**, в шапке показывать чипом «RU» с кликом
   для смены. Модалка остаётся только для случая «модель не скачана».
2. **Оставить модалку, но открывать её при входе в проект**, а не по «Старт».
3. **Автоопределение по первым 30 секундам** с возможностью переключить — но
   тогда первые реплики могут распознаться не той моделью; для многоязычной
   практики скорее вредно.

## 4. Минута до интервью — самое рискованное место

### 4.1. Нельзя убедиться, что запись действительно работает

**Что не так.** Есть полоски уровня (`vu-mic`, `vu-sys`) и подсказка «скажите
что-нибудь». Полоска доказывает, что в устройство идёт сигнал. Она не
доказывает, что: (а) распознавание загрузилось, (б) респондент попал в правый
канал, а не в тот же, что интервьюер, (в) слышно не эхо из колонок.

**Почему больно.** Цена ошибки — испорченное интервью, которое не повторить.
Это единственный необратимый сценарий во всём продукте.

**Решения:**

1. **«Проверка 15 секунд».** Кнопка в ⚙ и в строке готовности: пишет 15 секунд,
   гоняет через тот же конвейер, показывает две строки — «Вы: …» и
   «Собеседник: …». Если вторая пустая — «звук собеседника не попадает в запись»
   с ссылкой на нужный раздел. **Считаю это функцией №1 по соотношению
   польза/стоимость.** Стоимость: 1–2 дня, весь конвейер уже есть.
2. **Детектор эха/одного устройства.** Сейчас проверяется только `mic !== sys`
   (`canStart`). Добавить корреляцию каналов за первые 10 секунд: высокая
   корреляция → «похоже, вы работаете без наушников».
3. **Напоминание про наушники** одной строкой в диалоге старта — дёшево и
   покрывает самую частую ошибку (README:128 честно говорит, что
   эхоподавления нет).

### 4.2. Здоровье записи не видно во время интервью

**Что не так.** Всё общение с пользователем — одна строка статуса
(`setStatus`, `app/web/app.js:244`), которая перетирается следующим сообщением.
Если ASR упал, канал отвалился, LLM перестала отвечать — сообщение мелькнёт и
исчезнет. Истории нет.

**Решения:**

1. **Постоянная полоска здоровья** в шапке: три точки — запись / распознавание /
   подсказки. Зелёная-жёлтая-красная, наведение объясняет. Всегда на месте,
   читается боковым зрением за полсекунды.
2. **Липкий баннер для деградаций**, который не исчезает сам, пока не нажали
   «понятно» (отвалившийся канал — это потеря данных, а не уведомление).
3. **Журнал событий сессии** во вкладке «Транскрипт» вперемешку с репликами:
   «12:14 канал собеседника пропал», «12:15 восстановлен». Потом видно, какой
   кусок интервью потерян.

## 5. Во время интервью — ядро продукта

### 5.1. Слишком много интерфейса для человека в разговоре

**Что не так.** Экран интервью: гайд слева, три бокса справа (подсказки,
комментарии, «спросить дополнительно»), сверху — статус, таймер, темп, пять
вкладок. Всё требует чтения.

**Решения:**

1. **Режим фокуса как основной вид.** На экране: текущий вопрос крупно + одна
   следующая рекомендация + строка темпа. Всё остальное — по клавише или по
   наведению. Полный вид остаётся для тех, кто хочет.
2. **Периферийная сигнализация вместо текста.** Цвет тонкой полосы по краю окна:
   зелёный — идём по плану, жёлтый — отстаём, красный — пропущена обязательная
   тема. Это считывается без фокусировки взгляда — то есть работает в разговоре.
3. **Одна карточка вместо ленты из шести.** Сейчас `max_recommendations: 6`.
   Показывать одну, самую срочную, со стрелкой «ещё 5». Остальные — в отчёт.

### 5.2. Подсказки приходят по часам, а не по разговору

**Что не так.** `interval_s: 240` — анализ раз в 4 минуты. Карточка описывает
разговор, который был 2–4 минуты назад. Подписи «раздел → вопрос» и подсветка
свежих смягчают, но не лечат.

**Решения:**

1. **Триггер по событию вместо таймера.** Анализ запускается, когда: (а)
   исследователь кликнул следующий вопрос в гайде — то есть тема закрывается,
   (б) пауза дольше N секунд, (в) респондент выдал длинный монолог. Ритм
   интервью, а не ритм часов. **Это правильный ответ.**
2. **«Отбивка темы».** Явная кнопка «перехожу дальше» → немедленный короткий
   анализ «что в этой теме осталось недоспрошено», ответ за 10–15 секунд, ровно
   в тот момент, когда его ещё можно применить. Дешёвая версия п.1.
3. **Двухскоростной анализ:** маленькая модель на пробинг-вопросы каждые 60 c,
   большая — на сверку покрытия каждые 4 минуты.
4. **Честная подпись возраста:** «по разговору до 12:41» на карточке. Стоимость:
   час. Не ускоряет, но чинит доверие.

### 5.3. Флаг по F5 не работает там, где нужен

**Что не так.** Обработчик — `document.addEventListener("keydown", …)`
(`app/web/app.js:2124`). Во время интервью фокус в Zoom, а не в приложении.
Значит, самая быстрая функция продукта («отметь этот момент») требует сначала
кликнуть в окно.

**Решения:**

1. **Глобальный хоткей** уровня ОС (Windows: `RegisterHotKey`; macOS: требует
   разрешения Accessibility и честного объяснения зачем). Например
   `Ctrl+Shift+Space`.
2. **Полоса-«ушко»** поверх всех окон: узкая всегда-сверху панель на 40 px с
   одной кнопкой 🚩 и цветом состояния. Не требует прав, не крадёт фокус.
3. **Педаль/внешняя кнопка** (HID) — для тех, кто ведёт много интервью; звучит
   экзотично, но у транскрибаторов это норма.

### 5.4. Комментарий привязывается к вопросу, только если по нему кликнули

**Что не так.** Текущий блок ставится кликом по гайду (`S.curBlock`). В живом
разговоре это лишнее действие, поэтому большинство комментариев уедет без
привязки.

**Решения:**

1. **Считать текущую тему из анализа** (движок покрытия и так знает, о чём сейчас
   речь) и подставлять её как якорь; клик остаётся ручным переопределением.
2. **Автопродвижение:** тема помечена covered → якорь сам переходит к следующей
   не закрытой.
3. **Привязка по времени задним числом:** комментарий сохраняет таймкод, а
   вопрос присваивается на этапе отчёта, когда уже известно, что где обсуждалось.

### 5.5. Нет паузы

**Что не так.** Только «Старт» и «Стоп» (`startStop`, `app/web/app.js:1787`).
В реальном интервью бывает: «давайте это не под запись», перерыв, звонок.
Сейчас единственный выход — стоп (сессия закрывается, пишется отчёт) или
писать то, что просили не писать.

**Решения:**

1. **Пауза/продолжение:** аудио не пишется, в транскрипт уходит отметка
   «пауза 3:20–5:40». Одна кнопка, важна не только для удобства, но и этически.
2. **«Не под запись» на 60 секунд** — кнопка с автовозвратом, чтобы не забыть
   включить обратно (самая частая ошибка с паузой).
3. **Ретро-удаление куска:** «вырезать последние 2 минуты» — если попросили уже
   после того, как сказали.

## 6. После интервью — самая недоделанная часть

### 6.1. Результата нет в приложении

**Что не так.** `stop_session` пишет `report.md` и говорит «Report saved»
(`app/server/controller.py:512`). В UI отчёта нет ни одного упоминания. Человек
провёл час интервью и получил строчку статуса.

**Решения:**

1. **Экран «Итоги интервью» сразу после стопа:** резюме, покрытие тем, флаги с
   таймкодами, «спросить дополнительно», кнопки «копировать в Markdown»,
   «открыть папку». Это естественная точка, где человек и так сидит и ждёт.
   **Обязательно.**
2. **Отчёт как вкладка** у прошедшего интервью (в просмотрщике рядом с
   транскриптом) — чтобы к нему можно было вернуться.
3. **Экспорт в .docx/.pdf** — исследователь отдаёт результат команде, а не
   читает сам. Markdown-файл в папке для этого не годится.

### 6.2. Просмотрщик прошлого интервью не даёт работать с текстом

**Что не так.** Есть транскрипт + аудио + клик по строке = перемотка (хорошо!).
Нет: поиска, копирования цитаты с таймкодом, правки ошибок распознавания,
переименования говорящих, выделения фрагментов.

**Решения:**

1. **Поиск по транскрипту** (и по всем интервью проекта) — минимум.
2. **Цитата в один клик:** выделил → «скопировать как цитату» → в буфере
   `«…» — Респондент 3, 12:41`. Исследователи живут цитатами; это то, ради чего
   вообще открывают транскрипт.
3. **Правка текста сегмента** с сохранением в `transcript.jsonl` (ASR ошибается
   в именах и терминах, и сейчас это неисправимо из приложения).

### 6.3. Запись «без проекта» — тупик

**Что не так.** Кнопка «Record without a project» существует, но
`renderProject()` (`app/web/app.js:1524`) при пустом `projectId` показывает
заглушку и очищает список сессий, а `openProjectFolder` (`app/web/app.js:1422`)
отвечает «Choose a project first». Итог: записанное вне проекта не видно в
приложении никогда — ни списком, ни просмотрщиком, ни кнопкой «папка».

**Решения:**

1. **Виртуальный проект «Без проекта»** в списке — те же сессии, тот же
   просмотрщик. Стоимость: полдня.
2. **Убрать режим совсем:** «Записать» создаёт проект с автоименем
   «Интервью, 20 августа». Проект — не бюрократия, а просто папка.
   Меньше кода и меньше объяснений. **Предпочтительнее.**
3. **Перенос:** «переложить это интервью в проект» — нужно в любом случае,
   потому что первое интервью часто пишут «просто попробовать».

### 6.4. Серия интервью не сводится

**Что не так.** Есть агрегированное покрытие по темам (`coverageRowHtml`) — «в
скольких интервью тема закрыта». Это метрика полноты, а не находка. После
восьми интервью исследователю нужно другое: «что все восемь сказали про тему X».

**Решения:**

1. **Сводка по теме:** тезисы (`findings`) из всех сессий серии, сгруппированные
   по теме, с переходом к таймкоду. Данные уже собираются — нужна только сборка.
2. **Отчёт по исследованию** одной кнопкой: сквозное резюме поверх сводки тем.
3. **Карточка респондента:** псевдоним, сегмент, дата, заметка. Без этого
   «интервью №3» через месяц не опознать, а любой реальный проект начинается с
   вопроса «а это кто был?».

## 7. Этика и доверие

### 7.1. Согласия на запись нет нигде

**Что не так.** Поиск по `consent` в коде и документации не даёт ни одного
совпадения. Продукт записывает голос другого человека и не помогает соблюсти
единственное обязательное условие такой записи.

**Решения:**

1. **Строка в диалоге старта:** чекбокс «согласие на запись получено» + готовая
   формулировка, которую можно прочитать вслух. Факт и время пишутся в
   `meta.json`. Дёшево и снимает главный юридический риск пользователя.
2. **Первый автофлаг «согласие» на 00:00**, чтобы момент был слышен в записи —
   так делают в профессиональных исследованиях.
3. **Шаблон согласия в настройках проекта** (для разных стран и заказчиков).

### 7.2. Приватность заявлена, но не видна

**Что не так.** «Всё локально» — сильнейший аргумент продукта, но живёт только в
README. В интерфейсе его нет, а именно исследователю нужно уметь ответить
респонденту: «куда пойдёт запись?».

**Решения:**

1. **Строка на стартовом экране:** «Всё остаётся на этом компьютере. Ничего не
   уходит в сеть» + ссылка «что и где хранится».
2. **Экран «Данные проекта»:** размер записей, где лежат, кнопки «удалить
   аудио, оставить транскрипт» и «удалить интервью». Сейчас удалить интервью из
   приложения нельзя вообще, а проект с записями удалять запрещено.
3. **Явный переключатель «офлайн»** (даже если сеть и так не используется) —
   видимое обещание стоит дороже, чем невидимая реализация.

## 8. Язык и термины

Интерфейс переведён на английский осознанно, документация — на русском. Внутри
английского остались инженерные слова: `LLM`, `ASR`, `Parakeet`,
«Reconciliation analysis…», «utterances», «— as configured —». Исследователю
они не говорят ничего, а тревожность повышают.

**Решение:** словарь замен и один проход по строкам: LLM → Hints/Analysis,
ASR/Recognition model → Speech recognition, reconcile → Re-checking topics,
utterances → lines, «— as configured —» → «Same as last time». Стоимость: день,
эффект — на каждом экране.

## 9. Что бы я поменял на уровне концепции

Три идеи, каждая переопределяет продукт сильнее, чем список правок выше.

**1. Не лента, а один следующий шаг.** Продукт отвечает не на вопрос «что
происходит с покрытием», а на вопрос «что спросить сейчас». Всё, что не влезает
в один ответ, — в отчёт. Экран интервью должен читаться за полсекунды боковым
зрением.

**2. Ритм задаёт интервьюер, а не таймер.** Единственный жест — «перехожу к
следующей теме». Он и есть точка, где анализ полезен, где комментарий получает
якорь, где темп пересчитывается. Один жест вместо таймера, кликов по гайду и
ручных «Анализировать».

**3. Продукт заканчивается отчётом, а не файлом.** Стоп → экран итогов → цитаты
и выводы, которые можно отдать команде. Пока результат живёт в папке, продукт
остаётся диктофоном с подсказками, а не инструментом исследователя.

## 10. Вводные, которые сузили список

Ответы на вопросы, заданные по ходу разбора (2026-08-20):

- **Ставят только свои** — исследователь и коллеги. Значит, сборка с подписью и
  GUI-установщик (§2.1) снимаются с плана; хватает п.1 «переставить акценты в
  README». Бюджет уходит в сам продукт.
- **Интервью только онлайн (Zoom/Meet).** Модель двух каналов верна, диаризация
  не нужна, ветка очных интервью не открывается. Проверка звука (§4.1) остаётся
  первым пунктом: онлайн-маршрутизация — самое хрупкое место.
- **Помощь во время и разбор после ценны поровну** — берём верхние пункты из
  обеих половин, а не одну половину целиком.
- **Гайд читается с экрана** — раскладка «гайд слева» оправдана. Значит, лечим
  не «перестать смотреть в экран», а перегруз: одна карточка вместо ленты,
  крупный кегль, периферийный цвет как дополнение, а не замена. Глобальный
  хоткей опускается в середину списка (фокус всё равно часто в Zoom, но это уже
  не блокер), импорт готового аудио — тоже (живой сценарий важнее).
